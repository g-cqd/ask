## Open questions — not facts

The provider seam is gated by name, not proven by shape. Each of these is a claim with a probe that could
refute it; roadmap 0026 owns them.

- Sessions persist `StopReason.wire`, and its strings are Anthropic's. A second provider's stop reasons
  would be stored as `.other(...)`; is that lossy for resume or for the loop's decisions?
- `RequestBlock.thinking` requires a signature; OpenAI-style reasoning has none and some providers need
  opaque round-trip state (encrypted reasoning, thought signatures attached to tool calls). No place exists
  for provider-private state on a block.
- Tool results are `String`; images and structured content have no representation. A user turn is a `String`.
- `ModelRequest` carries model, token cap, system text, messages, tools. No reasoning effort, sampling,
  cache hints, or provider options. No model catalog, so no context window for compaction.

And for features other harnesses have (roadmap 0027): the loop reports through a closure, runs tools
sequentially, has no approval or hook point (0019 needs one), `ToolRegistry` is fixed at init (MCP tools
arrive later), `ToolDefinition` carries no read-only or concurrency metadata, `SessionPayload` is a closed
enum with no extension entries, and sub-agents, skills and prompt templates have no home.
