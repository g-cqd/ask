# Diary — 2026-10-18 (09)

## Asked to challenge my own claims, so I did

Three of this session's conclusions were load-bearing and under-probed. One turned out to be true and is
now properly evidenced; two were wrong about my own work and are corrected rather than defended.

## The claim that survived, after being tested properly

I had written that Terminal.app does not speak the kitty graphics protocol. That was **an argument from
absence** — it is not in TerminalKit's detection list — which is precisely what this repository's evidence
rule does not accept. So I probed it.

A script emits the same sequence in each terminal: clear, print text markers, transmit a solid image, place
it. The screen is then read back from **outside** the terminal — AppleScript for Terminal.app, `kitty @`
for kitty.

| Terminal | Screen readback | Verdict |
|---|---|---|
| kitty | `ROW0 MARKER AAAA ROW2 MARKER BBBB DONE` + `ESC _ G i=1;OK ESC \` | consumed, **and answered** |
| Terminal.app | `////AP///wD///8A////AP///wD///8A////…` | **rendered as visible text** |

Terminal.app does not interpret APC at all, so it cannot implement a protocol carried inside APC.
**CONFIRMED by behaviour.**

**The control is what makes it a probe.** kitty consuming the same bytes and replying with `i=1;OK` is
what shows the readback can detect consumption. Without it, "Terminal.app showed text" could equally have
meant the test was broken.

And it nearly did. The first run produced a blank screen, because I left a stray `time.sleep = None` in
the probe that crashed it before it printed anything — and a screenshot taken at that moment showed a full
row of green pixels that I nearly reported as "the green image rendered". It was not. It was a Terminal.app
UI element, and the decisive tell was that it was **1000 pixels wide where my image was 16 wide**. Had I
not read the screen back before trusting the picture, I would have reported a false positive — the same
defect as TerminalKit's first emulator harness, and the reason this diary keeps insisting that a probe
reads its own output.

## Two claims about my own work that were wrong

**The cold-start figure measured the wrong path.** The budget is *spawn to the prompt appearing on the
terminal's output stream*. I measured spawn-to-exit of `ask --budgets` — no terminal, no raw mode, no
frame — and quoted the 1.55 ms delta as "what `ask` links costs". It is an **upper bound that includes real
work**: argument parsing, building JSON, printing it. The white paper now no longer quotes it, and ADR-0009
carries the honest decomposition:

| Stage | median |
|---|---|
| `/bin/echo` spawn to exit | 2.05 ms |
| trivial Swift binary | 3.04 ms |
| `ask --budgets` | 4.59 ms (upper bound) |
| **`ask` TUI to first prompt** | **6.23 ms** (what the budget measures) |

**The module-count probe never ran a terminal either.** Its binaries had no TTY. The finding stands for the
load-time component only.

**What survives, and what the decision actually rests on:** cold start is 6.23 ms of a 25 ms budget. Even
if twenty targets cost a full millisecond — fifteen times what was measured — the total stays under 30% of
budget. **The fine-grained choice never depended on the probe.** It was justified by the headroom, and the
measurement only confirmed it. That is a much better position to be in than the one I claimed.

## The library products

Probed rather than skimmed: `Package.swift:67-68` declares `.library(name: "AskCore")` and
`.library(name: "AskTUI")`. Nothing imports either — `ask` is not a dependency of TerminalKit, Aemi or
Atelier. They are speculative generality, which the white paper bans.

**Decision: not removed here.** It is a pre-existing issue found mid-task, and the law says report rather
than silently repair. `0016` rewrites that manifest anyway and adopts a rule: **a product exists because
something consumes it** — each gets a named consumer or goes.

## A risk I glossed, now named

Putting the Claude gate in the `AskAI` adapter means relocating the system prompt into the first user
message. That changes the request's **prefix structure**, which is what prompt caching keys on. ADR-0007
records that pi's gate preserves `cache_control` markers, so the markers survive — but preserved markers
over a differently-shaped prefix may not hit the same cache.

Unprobed, and recorded as a question `0010` must answer before assuming relocation is free. If it is not
free, the alternative is a provider-specific context builder instead of a relocating adapter — a real
design cost, better discovered at `0010` than after.
