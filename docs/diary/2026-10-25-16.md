# Diary — 2026-10-25 (16)

## A trusted project may name MCP servers (ADR-0103)

ADR-0099 refused project-level servers outright. The project file already sits behind a gate (ignored until a person trusts it, with a
terminal), and the missing piece was that trusting said nothing about what it let happen. So the change is small: allow the section,
say what would start, and close the one new hole.

## What was built

`MCPSection.consent`, `MCPServerSetting.referencesEnvironment`, the project rule in `validateMCP`, and the lines in `ask trust`.
Probe D rewritten around a trusted project.

## What went wrong on the way

- **The hole I almost left.** Allowing the section would have allowed `${NAME}` in a project's `headers`, which fills from ask's own
  environment: a repository could have named a URL and a header of `${ANTHROPIC_API_KEY}`. I found it by asking what the expansion of ADR-0099
  does in a file the user did not write. It is refused at load, so also at trust.
- A mutant (an unterminated `${` counted as a reference) did not compile because it left a variable unused; rewritten, then caught.
- `ask trust` is the one place that prints for a person, and it lives in `Sources/ask`, which has no tests. The text is built in the
  library (`consent`) and tested there; only the printing is covered by the probe.
