# Diary — 2026-10-19 (06)

## ask developing ask: probes for binary and configuration reload

The user wants to develop ask from within ask, so it must reload its binary and its configuration (on demand
or automatically). Evidence and proposal: `docs/research/self-development-and-reload.md`.

**Decided by probes, not assumed:**
- A rebuilt binary is a new file (new inode). A running ask survives its own rebuild.
- Raw mode survives `exec`, so a re-executed ask finds the terminal as it left it.
- An editor's save-by-rename shows as DELETE on the watched file. The watcher must watch the directory and
  re-open the file.
- AemiJSON reads JSON5, so the config can carry comments.

**A probe mistake of mine:** the first rebuild probe ran in ask's tree while another session's `swift test`
held `.build/.lock`. My build waited and the probe timed out, with its output lost to Python's buffering.
Re-run on a scratch package. The lock wait is now a recorded requirement: a reload's build step must say it
is waiting.

The first rebuild of the scratch package kept the same inode, because a comment-only edit relinked nothing.
A real code change, confirmed by a content hash, produced the new inode.

**The proposal:**
- re-exec into the new binary with `--resume`, only between turns, after the build and a self-check of the
  new binary;
- layered JSON5 configuration with manual or automatic reload, validated whole;
- config paths write-denied to the agent, so it cannot widen its own sandbox through a reload.

Resume becomes a prerequisite and moves up.

## Endpoint Security, probed (objective-see/FileMonitor)

The user suggested FileMonitor's technology. It is Endpoint Security: system-wide events attributed to
processes. `es_new_client` from ask's kind of binary returns `ERR_NOT_PRIVILEGED`, with or without the
entitlement; it needs root, an Apple-granted entitlement and Full Disk Access.

FSEvents was probed alongside:
- recursive, by path, correct around renames;
- about 12 ms;
- its `OwnEvent` attributes only the watching process, not children.

**Conclusion:** use prevention (Seatbelt write-deny) for config safety, not attribution. Use kqueue for known
files and FSEvents for trees. Endpoint Security only via a future privileged helper. Two open points:
- FSEvents needs a dispatch queue, which `SourceStandards` bans, so it needs a written exception;
- the watcher belongs in Aemi.
