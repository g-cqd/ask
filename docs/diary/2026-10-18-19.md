# Diary — 2026-10-18 (19)

## The session file store, and the first rule-16 benchmark

`SessionFile` landed: append-only, damaged original kept beside its repair, create and fork never
overwrite (ADR-0017). Its first durability numbers came from Python. When the user made benchmarking
mandatory (ADR-0016), that stopped counting: a model of the syscalls is not the shipping path.

## Probes

- **fsync is not ordered on Darwin.** Read fsync(2) and fcntl(2): the drive may persist later writes
  without earlier ones. For an append log, that is a hole mid-file. For the rename-based repair, it is a
  renamed file whose bytes never landed. `F_BARRIERFSYNC` orders them. I had not measured it at all, and
  AemiIO already modelled exactly none / barrier / full, with a fallback my code lacked.
- **Barrier cost, through SessionFile, three runs:** p50 190–325 µs, p99 0.5–1.1 ms, max 1–5.8 ms.
  fsync was 28 / 39 µs; full is 2.75 / 3.7 ms. Barrier is the default, because the reliability principle
  needs ordering and the p99 fits the 2 ms action budget. The tail is recorded as a constraint on 0009:
  persistence stays off the input path.
- **My own O(n) per change.** Each change worked on `var next = tree` and adopted it after persisting,
  so copy-on-write duplicated the whole tree every time. Benchmarked at 10 µs / 181 µs / 1.86 ms for
  0 / 10k / 100k entries; after an in-place change with a checkpoint rewind, 9 / 11 / 8.3 µs. A test
  suite would never have shown this. The benchmark did, on its first scaling run.

## Mutations

All compiling mutations caught: damaged-open appends onto the fragment, original not preserved, second
copy overwrites the first, repair never swapped in, appends after repair into the damaged copy (needed
an internal write seam to reach), torn append appended after, failed change committed, each undo path
(checkout, entry, index, leaf), and the default flushes for create and open.

## Harness lessons

- **The mutation script misread failures.** It treated any `error:` line as a build error. Swift Testing
  prints `Caught error:` for thrown test errors, so four real catches showed as invalid probes. It now
  matches the compiler's failure lines, and a deliberate compile error is the control.
- **jemalloc does not build on macOS 27** (Homebrew tier 3: "C compiler cannot create executables").
  Benchmarks run with `BENCHMARK_DISABLE_JEMALLOC=1`; allocation counts will come from AemiTestKit.
- **The gate and the pre-commit hook covered different trees.** A benchmark file passed `quality.sh` and
  was blocked at commit. Both now check `Benchmarks/Benchmarks`.
- One test was wrong, not the code. After one failed write, the next change correctly rewrites instead
  of appending, so a second failure through the injected writer never happens.
