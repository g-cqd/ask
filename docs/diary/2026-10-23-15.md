# Diary — 2026-10-23 (15)

## Runner count and list — roadmap 0051, ADR-0066

### What changed

- `JobTable.summaries` and `JobTable.changes()` (AskTools) report the running jobs, in start order, and announce every start and end.
  `AgentConversation.background` forwards them as `ConversationUpdate.runners([RunnerInfo])` beside the binary watcher, in one task group.
- The status line says `· 2 jobs` after the activity. A click on those cells, or `/tasks`, opens up to five rows above the status line;
  `… N more` when they do not fit. The transcript shrinks by the same rows and gets them back.
- `FrameGeometry` carries the status row and the count's columns, so the click maps to what was drawn. The list is not content.

### Evidence

| Existing contracts | pointer 26/26, folding, code 9, input 19, SIGTERM-stops-jobs | Pass |

The PTY probe found a defect the unit tests had not: two clicks inside the double-click time at the same cell arrive as a **double click**,
and the handler accepted only a count of 1, so a quick second click did not close the list. Fixed (any count), and a unit test added
(red against the old pattern: 1 issue). Mutants of the new code: seven caught; two more needed a better test or mutant. "Any column
toggles" survived because the test clicked twice and ended closed; it now asserts after every click. "The list does not take transcript
rows" crashes the test process (a write past the buffer), which counts as caught.

`/help` gained a line, so the pointer probe's fixed rows moved by one and its wheel count (6 steps) no longer reached the start of the
conversation; both were updated, not loosened.
