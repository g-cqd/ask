## Runner tree and below-input strip, jobs first — roadmap 0062 step 1, ADR-0105

### Claims and evidence

- **The input precedes the strip, and Esc closes the strip without erasing the draft or stopping a turn.** `RunnerStripTests` was written against the old code,
  compiled, and failed with six expectation failures in two tests (`/tmp/lanes-red.log`). After implementation both pass. The old list was above the status;
  the status and prompt geometry are now moved up by the strip's row count.
- **One tree feeds count and strip; duplicate ids, missing parents, cycles and deep chains do not lose nodes or recurse.** Seven `RunnerTreeTests`: ordered
  preorder with child supplied first, orphan/self roots, first duplicate wins, cyclic components, a 10,000-node chain, active versus terminal states, and mixed
  kind count with depth in the strip. These tests followed the implementation; mutation evidence below, not claimed red-first.
- **The strip takes bounded rows, has an overflow count, and remains outside transcript selection.** Existing `RunnersTests`, picker-composer and picker-click
  tests were updated for the new layout; all 421 AskTUI tests pass. No-runner layout remains the old layout. Tiny-screen tests remain green.
- **A real job is counted, appears below the input, leaves the input clickable, and goes away when stopped.** `ASK_PYTE=/tmp/ask-pty/lib python3
  Scripts/probe-runners.py .build/release/ask`: 11 checks pass with a real loopback `http.server`, a PTY and a fake provider. The changed probe clicks the moved
  input at its displayed cell, types into the draft, closes the strip with Esc and checks the draft is intact. No physical terminal window was opened.

### Performance: same harness, interleaved A/B

Added `RunnerBenchmarks.swift`: one keystroke frame (layout plus diff), 120×40, 200 transcript lines, strip open, 0/5/50 nodes, 2,000 samples. It is the same source
on both sides. The old executable was saved before implementation, then the new one; three pairs were run through `BenchmarkTool`, old then new, alternating.

Commands:

```
cd Benchmarks
swift package benchmark --target RenderBenchmarks --filter 'runners/.*' --no-progress --format text
DYLD_LIBRARY_PATH="$PWD/.build/out/Products/Release" .build/out/Products/Release/BenchmarkTool \
  --benchmark-executable-paths /tmp/ask-lanes-render-before --command run --format text \
  --baseline-storage-path /tmp/lanes-baselines --grouping benchmark --filter 'runners/.*' --no-progress
# Same command with render-after, alternating three pairs, under /usr/bin/arch -arm64.
```
