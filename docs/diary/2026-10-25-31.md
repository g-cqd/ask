## What the review found, and what I verified myself

I did not accept its conclusions from thinking text. Each was reproduced.

| Claim (from the model's thinking) | Probe | Verdict |
|---|---|---|
| `/reload`'s self-check runs the new build with ask's own, already blanked, environment, so a provider that reads its key from the environment is refused | Interactive probe: provider `gw` with `apiKey: "$GW_KEY"`, then `/reload` (`/tmp/h2.py`, now `probe_reload_env_key` in `probe-interactive.py`) | **CONFIRMED, my regression.** Current main: "Not reloading: ... provider "gw" reads its key from $GW_KEY, which is not set". The binary from before the change reloads. Anthropic by environment only passed because that key is resolved lazily, which is why probe H missed it. |
| Withholding a variable ask itself uses to find its files moves them, because library defaults read the blanked live environment | A run with `environment.withhold: ["XDG_STATE_HOME"]` | **CONFIRMED, my regression.** The session was written under the real `~/.local/state`; before the change, under `$XDG_STATE_HOME`. |
| `ASK_*` blanking makes the self-check load a different configuration | Not tested separately | **Not verified.** It follows from the first finding (same cause, same fix), but I did not reproduce a changed provider choice. |
| Other child processes inherit the blanked environment and need a credential | Read every launch site: `git ls-files`, `pbcopy`, the watchdog | **Nothing found**: none needs a credential. MCP and jobs get the snapshot. |

## Fix

- `SelfCheck.run(..., environment:)`: the child runs with the launch snapshot (`LaunchEnvironment.values`); no argument means this process's own, as before. Red test first with a stub that ignored the parameter. The job launcher's environment conversion is shared, so there is one place that drops invalid names.
- Eight executable call sites (`SessionDirectory(project:)`, `CredentialFile.standard()`) now pass the snapshot. `LaunchEnvironmentStandardsTests` scans `Sources/ask` for a read of `ProcessInfo` or `getenv`, and for those two calls without `environment:`. It was red on the eight sites before the fix, and I deleted a third test of mine that only re-checked a string literal.
- Probes: `probe_reload_env_key` (H2) is red on the regressed build and green on the fix and on the pre-change build; `probe-config-environment.py` case 5 is red on the regressed build and green on the fix.
