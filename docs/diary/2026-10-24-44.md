# Diary — 2026-10-24 (44)

## Skills before subagents, and the runner tree: the review the owner asked for

The owner's direction: skills matter more than subagents; subagents are off by default; a subagent lane is focusable; agents and the subagents
of subagents are visible below the input as in Claude Code, and as a tree in a sidebar. Nothing was built. The output is a design note
(`docs/research/skills-and-agents-design-2026-10.md`), three roadmap entries (0061 skills, 0062 the runner tree, lanes and sidebar, 0063
subagents off by default), and two pointers (0048, 0015).

### The one probe

The owner's `~/.agents/skills`: 26 skills, `~/.claude/skills` a symlink to the same set (so deduplicate by real path), frontmatter with
`name`, `description`, `allowed-tools` (21 of 26) and `metadata` (3), one quoted name that differs from its directory, at least four symlinked
skills, bodies of median 11.7 KB and up to 31 KB, and an advertisement (name, description, path) of about 11,400 characters, roughly 2,850
tokens by characters divided by four. That is an estimate from one collection and not a tokenizer's count; it is enough to say the cost is
real and needs a cap and a stable, cacheable prefix.

### Second direction from the owner: any harness's skills, and the most permissive parsing

The owner then asked that the skill tool pick skills from **any harness's locations unless an argument says otherwise**, and that **parsing of
tools and models be as permissive as possible**. I probed the machine for what that has to cover:

- Eight harness skill directories (`~/.claude`, `~/.agents`, `~/.codex`, `~/.pi/agent`, `~/.config/opencode`, `~/.vibe`, `~/.copilot`,
  `~/.gemini/config`) are **symlinks to one `~/.agent-harness/skills`**, so the union of every harness's location is one set seen eight times:
  real-path deduplication is required. Separately: 9 bundled Antigravity skills with no overlap, `xcode-skills` (10), and per-extension or
  per-plugin skill directories. Project-level skill directories found in `~/Developer`: only `.agents/skills` (2); the other harnesses'
  project paths were found in none, so they are proposals.
- 147 unique files (skills, bundled skills, 84 agent definitions in six harness formats, 28 of them TOML) have **different shapes for the same
  field**: `tools` as a comma string, a flow list, or a block list in another harness's vocabulary (`view_file`, `grep_search`, `run_command`);
  `allowed-tools` as a block list; `model` as one alias, as a list of display names such as `"Claude Opus 5.5"`, or an alias followed by a comment
  that holds `fallback_models`; descriptions mostly as block scalars; a quoted name. Nothing was rejected by the throwaway parser's container
  step; the contract in the note is written from these shapes, and the first real probe is "zero rejected" over the same files.
- The design is changed accordingly: sources table with ids and a `from` argument that can only narrow, a parser that cannot fail, tool lists that
  can only restrict or annotate and never add, models as preference lists resolved on the active connection and never leaving it by themselves.
  Three new questions for the owner are in the note (bundled sources, other-provider models, comments as hints).

### What this does not establish

Claude Code's behaviour is taken from the vendor documentation as the research note recorded it; none of it was seen running. Every decision
in the note is a proposal with its reason, and the questions for the owner are listed at its end. The ranking of skills above subagents is the
owner's; the reasons I give for it (smaller change, already used daily, no unattended spending, exercises trust, picker and cost budget that
subagents also need) are supporting, not the cause.

### Choices worth a second look

- The `skill` tool rather than the model reading `SKILL.md`: it keeps `SessionPayload` closed, works under `read: 'workspace'`, and costs one tool
  definition. The cost of that choice is a tool in every request when skills are on.
- Jobs first in the lane strip, so the whole UI can be built and probed with real processes before a single subagent exists.
- The sidebar for the character layout first, without waiting for the pixel work.
- Subagent enablement user-level only, so a repository cannot make a session spend tokens.
