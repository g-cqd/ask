# Diary — 2026-10-20 (47)

## Where the interaction work stands

The owner asked for the probes and for work on every topic. The terminal probe, and the mechanisms for regions and clicks, selection and
the clipboard, and folding, are in TerminalKit (its ADR-0028 to 0031 and diary 2026-10-20 (2) to (5)). This is the ask side: what that
changes here. No ask code changed; ask's pin of TerminalKit is untouched.

What changed in the plan: roadmap 0051 now lists what the kit offers and what it lacks, and says what ask would have to supply (a stable
identity per block, a per-row record of what is drawn, and placeholder text). ADR-0046 fixed the defaults earlier today.

### What is not done, in the order it would be done

1. **Painting the selection highlight** and a **drag controller** (anchor and head edges, autoscroll, a click inside a selection), in the kit.
2. **A screen that registers regions and records provenance** each frame, in ask, with the first click: the thinking block, then the runner
   count. Nothing has met a real layout yet, so this is where the untested assumptions will show.
3. **Images** and **long code**, in the kit, and last: images are in under 1% of messages.
4. **The bounded input** (kit roadmap 0019), which also owes ask the wrapped-line navigation of roadmap 0049.
5. **The `ui.*` configuration keys**, with the screen that reads them, so they are not added unused.

### What went wrong

- **A lot was built that nothing uses yet.** Three mechanisms are in the kit with tests, measurements and mutation checks, and no screen
  consumes any of them. That is the order the dependencies fall in, and it still means the risky part, a real layout recording provenance
  cheaply every frame, is ahead and not behind.
- **I counted my own mutation checks, and several of them were wrong first**: two did not compile, one was written backwards. They were
  redone, and each diary says so, but the pattern is that I wrote them quickly.

### Not verified

Everything about ask itself: no ask code uses the kit's new types, and no terminal has been dragged across two blocks with the clipboard read back.
