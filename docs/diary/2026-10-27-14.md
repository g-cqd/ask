### Duplicated Responses replies: reproduced, not guessed

An isolated live `/responses` request using the existing Copilot access token returned
HTTP 200 for `gpt-6.1-sol`, prompt `Reply only with AUDIT.`, max_output_tokens 32.
The probe refused redirects and validated the HTTPS Copilot origin; it did not refresh,
write credentials, enable policies, or print authentication headers. Returned usage
reported 12 input and six output tokens. This was a real authenticated request, not
an offline test; it does not establish quota/billing parity.

The service rotated response/item IDs on EVERY event, while all events for the sole
message retained output_index 0. Text deltas were AUD and IT; output_item.done then
carried AUDIT under another ID. The old decoder followed IDs exclusively, producing
three text blocks and the stored/displayed AUDITAUDIT. This reproduces the earlier
Hello!Hello!/testtest symptom by mechanism, rather than guessing at text duplication.

The sanitized fixture preserves identity differences, order, indexes and text while
removing credentials/headers, opaque IDs, account/safety identifiers, irrelevant fields
and billing extensions. It is explicitly NOT byte-exact. The raw response also had
copilot_usage in response.completed; its unit semantics remain unverified and were
not silently treated as credits or currency.
