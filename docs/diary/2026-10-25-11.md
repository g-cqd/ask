# Diary — 2026-10-25 (11)

## MCP servers reach the model (ADR-0099, roadmap 0067 phases 3 and 4)

After the client (diaries 07 and 08), the part with consequences: configuration, a registry that can change, a host that connects in the
background, a hub that outlives the loop, and the rules about the sandbox and about a project naming a program.

## What was built

`LiveTools` and `ToolRegistry(live:)`; the `mcp` config section (`MCPServerSetting`, `MCPSection`, `ConfigurationFile+MCP`); in
`AskTools`, `MCPToolAdapter`, `MCPToolName`, `MCPResultText`, `MCPExpansion`, `MCPHost`, `MCPHub`, `MCPReport`; in `ask`, the
composition, `/mcp`, the notices and the one-shot wait. Two probes through the real binary.

## What went wrong on the way

- **The first host never settled.** `waitUntilSettled` awaited the per-server task, and that task also followed the connection's events
  until it closed, so it ended only with the server. Following is now a task of its own.
- **A server still starting could outlive `stop`.** A connection was registered after its handshake, so stopping in between missed it.
  It is registered before. (Cancellation turned out to reach the handshake too; the registration is what makes the race closed.)
- **Line-length and complexity lints** sent me back twice (a validator at complexity 11, a function one line over 60); the structure
  test also caught a test file at 265 lines. Each was split, not accepted.
- **A quality-script reformat silently defeated a scripted edit.** I replaced text in the hub with a Python `replace` that did not assert,
  the formatter had rewrapped the lines, and the notices test then failed for a reason that looked like a race. The edit now asserts.
- **A false alarm about the renderer.** The raw screen after two notices looked corrupted ("…went away.nfig/ask/config.json."), and a single
  notice seemed not to paint until a key. Before touching AskTUI I read the harness: pyte does not implement scroll regions, which the
  app uses, so only a repaint is a picture. The app was right; the probe now waits on raw bytes and looks at a repaint.
- **`/help` grew a line again**, which broke `probe-pointer.py` (its wheel count and its list of known prefixes). I ran every probe suite
  this time, as the standing rule says, and fixed the two places; the wheel count no longer depends on the number of commands.
- Three mutants survived. Each was either equivalent (a host with no servers does nothing) or redundant code (a second withdrawal of
  tools that the server's closing already makes), so the code went, not the mutant.
