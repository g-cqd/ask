# Diary — 2026-10-23 (17)

## The host copy reports how it ended — roadmap 0051, ADR-0068

### What changed

- `HostPasteboard.run` starts the pasteboard command with the text on its standard input and reports `copied` or `failed(reason)` from its
  exit; a deadline (5 s) terminates a hang. `ScreenClipboard.copy` returns the notice for now and calls back once with the final one.
- The status line goes *Host copy pending* → *Copied to host clipboard* or *Host copy failed: pbcopy exited with status 1*. The terminal
  route still says only *Copy sent to terminal*. The controller numbers copies and drops a late result of an older one.
- `ScreenSession` is a file of its own now (a move, no change), because the new event pushed `InteractiveScreen.swift` over 250 lines.

### Evidence

| Claim | Probe | Result |
|---|---|---|
| A copy is finished when the command exits 0 and received exactly the text | `HostPasteboardTests` with real `sh`, 1.6 MB through the pipe, `false`, a missing path, `sleep 30` under a 0.3 s deadline | Pass |
| Notices for terminal, host and both routes, success and failure | `ClipboardFeedbackTests`, `ScreenClipboardTests` | Pass |
| A late result cannot overwrite a newer copy; a success does not revive a cleared notice; a failure does show | `CopyGenerationTests` | Pass |

Six mutants of the new code were caught: no SIGPIPE protection, ignored exit status, stale results applied, cleared notices revived,
failures reported as copied, a terminal failure hidden by a host success.

The first run of the tests **killed the test process**: the "exits before reading" case wrote to a closed pipe and SIGPIPE ended it. The
same hazard was in the old `pbcopy` code and would have ended ask if `pbcopy` ever exited early. Without the `F_SETNOSIGPIPE` line the
test process still dies, which is what makes that test a control.

### Not verified

The wiring in `ScreenSession` (six lines that start a copy and post its result) has **no end-to-end test**. The mock terminal's input ends
the instant its buffer is empty, which races the asynchronous result, and a real-binary PTY probe would have to run the real `pbcopy` and
overwrite the owner's clipboard, which I did not do. The pieces on either side are tested; the glue is not. A deliberate, consented probe
on a terminal that needs the pasteboard (Terminal.app), or an injectable command path, would close it.

### What remains

Subagents as runners, a way to stop a runner, images, input autoscroll and mouse placement, and physical-terminal, tmux and SSH checks.
