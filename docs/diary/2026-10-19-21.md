# Diary — 2026-10-19 (21)

## Configuration files, layers, trust and reload (roadmap 0039, ADR-0032)

The user asked for JSON that AemiJSON can speak, JSON5 for example, probed first, usable in a file named
`.json`, and for every bug found to be reported to AemiJSON and fixed there.

### The format, probed

- **Reference:** `json5` 2.2.3 under bun. Corpus: 51 JSON5 cases and 10 strict ones.
- **Result:** AemiJSON's JSON5 mode agrees on 49 of 51, Foundation's on 47 of 51. Strict JSON reads the same
  in AemiJSON's strict and JSON5 modes.
- **A false alarm first.** The emoji case disagreed. The cause was my probe, which escaped by scalar where the
  reference escapes by UTF-16 unit. Fixing the probe removed the difference, and that alone justified probing
  before reporting.
- **Three real findings, reported as issues 1 to 3 on AemiJSON** and not worked around:
  Unicode whitespace and U+2028/U+2029 in JSON5, leading-zero numbers accepted, and `.throwError` missing
  duplicate keys that differ only by escapes (the first wins).
- **Where the bugs are** is in the issues, with file and function names. I did not fix them: the user said to
  file them and deal with them later.

### Built

`Configuration` (layers and sources), `ConfigurationFile` (the reader), `ConfigurationLoader`, `ProjectTrust`,

### What testing found

- **A mutation escaped:** flags below the environment. No unit test set one key from both. The probe covered it,
  the unit suite did not; a test was added.
- **A review of my own code found a real defect:** I read `errno` after `FileManager.contents` returned nil,
  which cannot tell a missing file from an unreadable one. An unreadable project file would have been taken for
  an absent one. A test failed first, then a reader on `open` and `read` fixed it, with a 1 MiB cap.
- **Three invalid mutants.** One used a method I had made up, two were duplicate `case` labels that Swift
  refuses. Re-written as expressions that compile.
- **The probe emulator was wrong, not ask.** The first run of the reload probe showed `Answer 2.` drawn over a
  notice. The raw bytes were `ESC[1;28r`, `ESC[1S`, then text at row 28: correct terminal behaviour. The
  emulator ignored the scroll region and scroll up, so every new line overwrote the last. Earlier probes only
  looked at the newest line. It now handles both. I nearly blamed the other session's scroll-region work.
- **Cold start:** the first A/B at load average 12 showed +1.5 ms at the median, with identical p10. 200
  interleaved runs showed +0.07 ms. Cross-run numbers on a loaded machine were again the thing not to believe.

### A security gap, and the damage I did to the credentials

- **The gap.** The agent has a bash tool, and nothing yet stops it from writing `~/.config/ask/` or running
  `ask trust`. `ask trust` now exits 77 without a terminal on standard input. Live, the real model told to run
  it got exit 77 and no trust store appeared. That is a speed bump: a pty can be allocated. The wall is the
  sandbox (roadmap 0017). The ADR says so and limits project-file keys until then.
- **The damage.** For a live test I symlinked `credentials.json` into a temporary config directory. The token
  had expired, so that run refreshed it. ask's atomic save replaced the symlink with a file in the temporary
  directory, and the refresh token the real file held was invalidated server-side. The next run failed with
  `invalid_grant`. The new tokens were still in the temporary directory; I copied them back (owner-only) and
  verified a real run. **Never share a credential file between config directories: refresh tokens rotate.** Live
  tests now use the real config directory and a project file, and untrust afterwards.
