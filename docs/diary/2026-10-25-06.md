# Diary — 2026-10-25 (6)

## Skills, phase 2: the advertisement and the `skill` tool — roadmap 0061, ADR-0095

The owner answered the cap: **32**.

### What was built

`SkillAdvertisement` (the prompt block), `SkillLookup` (find by name among what a selection allows), `SkillTool` in AskTools, the `skills` configuration section
(`enabled`, `maxAdvertised`, `sources`; a project's file may only turn skills off), `SkillBook` in the composition root (built with the loop, on the first
prompt), `Scripts/probe-skills.py`, and a faster discovery. ask's own skills directory now follows `$XDG_CONFIG_HOME/ask/skills`.

Twelve mutants of the advertisement, lookup, tool and configuration were run in two rounds. One survived at first (the list was not sorted, because discovery
already returns names in order within one directory); the test now puts the names in three harnesses so precedence order and name order differ.

### The cost was the surprise

`ask skills` first took 47.6 ms against 8.3 ms for the parser alone. The stages were timed one by one, which showed the time was not where I would have put it: eight
symlinked directories searched eight times, every skill body split into lines by *character*, and a digest made by 32 `String(format:)` calls. After the three
fixes it is 16.4 ms (p25/p50/p75 15.7 / 16.4 / 17.3, 40 runs, one-minute load 3 to 5, not idle). Cold start is unaffected: nothing runs until the first prompt.

### Budgets, with the skill tool in the loop

`Scripts/measure-budgets.py`, 20 runs, ordinary release binary, one-minute load about 4 (not idle): cold start 19.37 ms median (p95 24.80, max 33.41), idle RSS 9,360 KiB,
input 0.47 ms (p95 1.19), action 1.86 ms (p95 2.42). All medians inside budget; nothing in discovery runs at launch. `probe-agent-run.py` (157 checks) passes; its
"tools offered" check now ignores the optional `skill` tool, because on a machine with skills the list has nine.
