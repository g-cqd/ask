## Closing the parent-environment exposure (roadmap 0072, ADR-0112)

Worktree `ask-conceal`, numbers reserved with `Scripts/next-number.sh --claim`. No Agora. The decision and its probe table are in ADR-0112.

## What happened

- Tried to deny the `KERN_PROCARGS2` read with Seatbelt first, since a rule would have been the smaller change: six variants, and ask's own restricted-read profile, all failed to stop it. Seatbelt does not gate this call.
- Tried `unsetenv`, the obvious fix, and refuted it. My first version of that probe exec'd the process, so the new image got the cleaned environment and the test said "fixed"; it could not fail. Redone with `fork`, it showed `unsetenv` leaves the secret and overwriting the string removes it.
- Implemented the launch snapshot and the in-place blanking (about 20 `ProcessInfo` reads in `Sources/ask` now read the snapshot). Red tests first; all four were red against a stub for the right reason, then green. One test was wrong (it saw variables set by its neighbours) and I fixed the test, not the code.

## Probes

| Claim | Probe | Verdict |
|---|---|---|
| The tracked parent-environment probe works when reads are restricted | Python reader under `--read workspace` | **INCONCLUSIVE**: the interpreter could not run there, so it neither recovered nor was denied. Replaced by a C reader piped to `cc`, which runs in both modes. A first heredoc version failed on the denied temp file. |
| The probe can fail, and the fix is what turns it green | before: `ask-env-final`; after: new build | **CONFIRMED**: before, exposed in both modes (exit 1); after, entry present and blank in both (exit 0). The probe requires `SCANNED` or `DENIED` in the output, so a run that never read anything is exit 2, not a pass. |
| Skipping `LaunchEnvironment.conceal` is caught | Comment out the call, rebuild, run | **CONFIRMED**: exposed, exit 1. |
| A `conceal` that writes no bytes is caught (the `unsetenv`-style false fix) | `memset(..., 0, 0)` | **CONFIRMED**: exposed, exit 1. Both mutants restored and compared byte for byte. |
| `/reload` into a new build still finds the key | probe H of `probe-interactive.py` (pyte at `/tmp/ask-pty/lib`) | **CONFIRMED**: 14 checks pass. |
| The `Reexec` change is necessary, not decoration | Put `execv` back | **CONFIRMED necessary**: "the next prompt works in the new process" fails and the session has no second response. Restored. |
| Nothing else regressed | `probe-agent-run.py` on the final binary; `probe-bash-environment.py`; `probe-config-environment.py` | **CONFIRMED**: 157 checks, exit 0; both environment probes exit 0. Both binaries are fresh `swift build -c release --scratch-path` builds of the same base (`2c744fd`) with and without this change. Median [min,max]; ms except memory in KiB:

| | Before | After |
|---|---|---|
| Binary, bytes | 14,032,944 | 14,040,912 (+7,968) |
| Cold | 12.211 [11.018,12.608] | 11.990 [11.044,13.999] |
| Idle RSS | 9824 [9808,9840] | 9832 [9808,9872] |

Rebuilt both from the same commit. A size comparison across different bases proves nothing.
