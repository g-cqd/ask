# Diary — 2026-10-19 (15)

## Jobs and waits (roadmap 0031, ADR-0029)

The work happened on branch `jobs`, rebased onto the other session's providers, hooks and TerminalSession
work. Three conflicts were merged by hand: the screen's shutdown closure, `makeLoop`, and the screen call.

### Built

- **Every `bash` command is a `Job`** in a shared `JobTable`. `yield_seconds` leaves a command running as a
  job.
- **Tools:** `wait` (job end, text, file, port), `job_input`, `job_stop`.
- **Whole output** goes to a file, kept and named when the result is cut.
- **ask stops its jobs on every exit it can see.**

### What the tests found before any probe

- **A file-wait race.** The deepest existing directory was chosen, the directory then changed, and only after
  that was the watch set. The change raised no event, so the wait never ended. The fix is to look again
  after setting the watch. 20 of 20 runs passed afterwards.
- **A text split across a report was never found.** I first seeded the waiter from unread output only, but
  `bash`'s yield had already handed that output to the model and cleared it. A 4 KiB window of all recent
  output now seeds new waiters.
- **A port test took 15.6 s.** Probed: macOS drops IPv4 connections to a port that is bound but not listening,
  and `connect` returns `ETIMEDOUT` after 7.9 s, while IPv6 and unbound ports refuse at once. Connects are
  now non-blocking and bounded at 250 ms; that is a real-world state too, between a server's `bind` and its
  `listen`.

### Mutations

12 compiling mutations were caught; the probe-level ones are the two exit paths.

| Mutation | Verdict |
|---|---|
| Carry not kept across chunks | escaped, until the split-text test existed |
| "Port never retried" | escaped: `until` returning was read as success; now it returns whether it connected |
| Removing the stop on a screen signal | caught by screen probe E |
| Removing the stop when `-p` ends | caught by probe G |

Three mutants hung the suite past its 1-minute time limit. Two causes:
- tests awaited unstructured `Task {}` blocks, which the limit's cancellation never reaches; these are now
  `async let`;
- TestClock sleeps appear not to honour cancellation.

Per-mutant runs are now capped at 120 s. The user saw two stalls ("seems stalled", "seems hung") before that
cap existed, and one aborted mutation run left a mutant in `Job.swift`. It was found by grepping for the
mutant text and restored before anything was committed.

### Gate findings, fixed rather than accepted

- **dolly** found five clones in the new tools. Fixed with `JobAccess`, `JobTool`, shared
  `JobWaiting.watch`/`expiry`, and `PortWait.loopback`. One was accepted with a directive: the job tool's
  shape.
- **The structure gate:** `Job.swift` was over 250 lines, so waiting moved to `Job+Waiting.swift`. A test
  file had three types, and a source file two.
- **SwiftLint:** 7 parameters, so the launch parameters became `Job.Launch`.

### Live

Asked plainly to serve, check and stop, the model used `bash` with `yield_seconds`, `wait` on the port,
`curl` and `job_stop`, and replied "Directory listing for /". The port was closed afterwards.

The first live run showed `job_stop` as ✗: a requested stop was reported as the command failing. It is now
a success.
