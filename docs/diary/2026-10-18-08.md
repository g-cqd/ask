# Diary — 2026-10-18 (08)

## Two decisions, and what each one cost

Claude and Spettro first; both layouts first-class. Both are recorded as ADRs rather than as roadmap
notes, because each constrains more than the entry it was asked about.

## Claude, then Spettro

Probed `pi-integrations` rather than assuming the two were interchangeable. They are not, and the
difference is the useful part:

| | `api:` | Auth |
|---|---|---|
| `claude-subscription` | `anthropic-messages` | OAuth PKCE S256, pasted `code#state`, **real** refresh token |
| `spettro` | `openai-completions` | browser → poll every 2 s under a 10-min deadline, Bearer, **no real** refresh token |

Two protocols, so two genuinely different tool-call encodings — `tool_use`/`tool_result` blocks against
`tool_calls`/`tool` role messages. One provider would have hidden the provider seam behind an interface
that happened to be Anthropic's shape. This pair does not.

Spettro's `refreshToken` returns its own credentials unchanged, because the "refresh token" is a
duplicated device key. That is the kind of detail that quietly breaks a shared auth abstraction, so it is
in ADR-0007 rather than left to be discovered during `0011`.

## The constraint that reached back into `0009`

Reading the two providers surfaced something larger than the provider choice.

**Claude subscription inference is gated by a fuzzy prompt-content classifier**, derived by live
bisection against the backend on 2026-10-16 and documented in
`pi-integrations/src/domains/claude/gate.ts`:

- The system param's first block must exactly equal one canonical identity line; generic first blocks get
  `429`.
- Third-party harness prompts in the system param after block 0, **or as system-role messages anywhere**,
  trip it.
- The same content passes cleanly carried as blocks inside **user** messages.
- Headers, betas, tools, metadata and `max_tokens` are irrelevant to the gate.

So `ask`'s system prompt cannot live in the system param. It has to ride in user messages, behind one
canonical first block — which is Claude Code's own `<system-reminder>` pattern, and the fact that a
first-party tool works around it that way is itself evidence the constraint is real.

This is an **architectural** constraint on the context builder in `0009`, not a provider detail. Cheap to
design around now; expensive afterwards, because retrofitting re-plumbers every request and the failure
reads as rate limiting rather than as a prompt-shape rejection.

**Not re-probed here.** These findings are read from a working, tested implementation, not re-derived
against the backend. ADR-0007 says so, dates the source at 2026-10-16, and carries a follow-up to
re-verify before relying on it.

## Both layouts

0015 left the fork open. Both, ADR-0008.

The cheaper answer — one cell layout, pixels as refinement — caps compactness at the cell grid, which is
the thing pixels exist to escape. What I had not established before probing is *how much* the layouts
actually diverge, so I read `ChromeElement`:

- `.fill` and `.line` are decorative. A character layout approximates both with cell backgrounds and
  box-drawing runes.
- **`.bar` has no cell-grid equivalent.** A rect at a pixel offset inside a cell cannot be expressed in
  characters at all.

So the layouts are not redundant, which is exactly what defeats "baseline plus refinement" — for the one
element that motivates the work. A scrollbar thumb at 40% is four characters in any cell UI and one
placement here.

**The fallback is a real audience, not a hedge.** Installed and speaking the kitty protocol: kitty,
ghostty, wezterm. Falling back: **Terminal.app, at `/System/Applications/Utilities/Terminal.app`** — it
ships with macOS, so it is on every machine — and Orion RC. I looked in `/Applications` first and it was
not there; it lives in `/System/Applications/Utilities`, which is worth remembering because the obvious
check says "no Terminal.app installed" and is wrong.

Two layouts drift unless something forbids it, so ADR-0008 states the parity contract: identical
information architecture, ordering, visibility, actions, key bindings and reading order; free to differ on
how structure is drawn, spacing, density, colour and the thumb. The test is whether a user would have to
*learn* something new.

## Consequences accepted, not avoided

- The UI surface roughly doubles. That is the price of a compact layout that is actually compact.
- **`0003` becomes load-bearing for correctness, not polish** — it selects between two shipped layouts, so
  a wrong answer shows the wrong interface rather than a missing decoration. That raises its priority.
- `ask` needs its own gate-rejection diagnostic. The provider's own failure is a one-line "out of extra
  usage", indistinguishable from a genuine quota problem.

## Still open, and deliberately so

- **The character layout's density budget is undecided** — how compact it can be before it stops being
  legible. Written into `0015` as owed rather than guessed.
- **Which layout is the default when capability is unknown** falls to `0003`'s degraded-mode policy. Not
  decided here, because it belongs with the entry that owns detection.
- `0014`'s live numbers are still owed — no controlling TTY in this environment.
