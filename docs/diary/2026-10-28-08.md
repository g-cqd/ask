### MCP images

`MCPResultImages`: a server's image block is decoded, sniffed (declared type ignored), bounded with the provider's allowance, at most
8 per result; the text names each as shown or not shown with a reason. Wired through `MCPToolAdapter` and `MCPCallTool`.

### Context cost per image

Measured "tokens in" through Copilot (baseline included): claude-haiku-5.5 text 5.4k, 64×64 5.4k, 128×128 5.4k, 2000×1500 noise
9.3k; gpt-6-luna 2.3k, 2.3k, 2.4k, 5.9k. So a small image is nearly free and a large one 3.6–3.9k tokens. `Compaction.size` now
counts 12,000 bytes (3,000 tokens, gemini-cli's figure; Codex uses 7,373 bytes) per image, never the base64 length. Provider-reported
usage still drives the compaction trigger.

### Persistence by content hash

Pictures are written to `<session dir>/images/<sha256>` (0600, directory 0700, atomic rename, written once however often read); a
record holds the hash. Inline base64 sessions still open. A missing or altered file (hash mismatch) degrades to a line of text in the
result. This was also a correctness fix: the log's line limit is 1 MiB, so a 4 MB inline picture would have been dropped as a too-long
line on resume. Forks share the directory. Orphan files are never removed (ask has no session deletion).

### PDF: text first

PDFKit extracts text (31-page, 90 KB test PDF: 119 ms first use, ~2.9 KB ≈ 750 tokens a page) against 1.5k–3.9k tokens for a rendered
page. `read` now returns text for pages with ≥ 80 characters of text layer and pictures for the rest; `render: true` forces pictures;
a call is bounded by 100 KB of text and the picture cap. Native PDF upload (Anthropic `document`, Responses `input_file`, Gemini
`inlineData`) was not built: it costs at least pictures, excludes text-only models, and needs three wire shapes. Live: haiku-5.5 read the
text PDF correctly through Copilot. PDFKit linking: +0.16 MiB RSS, <1 ms in a minimal program. `measure-budgets.py` under 8 busy
workers: cold start 57 ms, input 6.8 ms (both over under that load), idle 13.1 MiB, active 22.9 MiB (over 20; known, 0088).
