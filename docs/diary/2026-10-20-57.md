## Falsification and corrections

- 17 parser/resolver/id mutations: each ultimately killed with source restoration checked. The first repeats-kept mutation
  removed the last use of `seen` and failed compilation: **not evidence**. Redone while retaining the use, it fails the duplicate
  record test. Initial model-list tests were written alongside the implementation, not red first; the mutations supply their
  observed failures and this is not claimed as red-first TDD.
- Six CLI mutations ultimately killed: ignored cache, unsafe names written as paths, empty name written as a path, refresh
  ignored, a false default marker, and damaged cache hidden. The first unsafe-name mutation still retained the character guard,
  so its survival did **not** test the intended fault. Redone by removing that actual constraint; the script fails as intended.
- Eight single-model lookup mutations ultimately killed: scope ignored, expiry off by one, future date accepted, prefix id
  matching, invalid entry accepted, new schema version accepted, unlisted model throwing, non-array models accepted.
  Two real gaps were exposed: new-version and non-array fixtures had bad headers too, masking the missing checks. Added
  otherwise-valid headers, reran, and killed both. The first future-date mutation was equivalent for the tested time; redone
  to accept a finite future date, and the existing test fails. All restores verified.
- Final parser edge checks found that a malformed `providers` field discarded an otherwise intact model. Four inputs failed
  the new test before wrapping that field leniently; the fix keeps the model and its other window. The total model-id limit
  now includes the leading tilde rather than accidentally permitting 129 bytes. Both guards were separately mutated.
- Swift Testing's macro failed to handle throwing optional calls compared directly to nil: binding the result first compiles.
- The first raw-subtree lookup returned nil: `JSON.withRawJSONBytes` needs container spans enabled. Reading the dependency's
  actual contract showed `JSONDecoder.decode(_:from: JSON)` reads a parsed node directly. The replacement parses once and
  decodes the header and selected entry from that tape. No unsafe buffer operation was added.
