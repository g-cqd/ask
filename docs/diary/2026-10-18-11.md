# Diary — 2026-10-18 (11)

## The signal handler could not deliver, and installing it was worse than the bug

`ask`'s roadmap 0006 wanted the reset ladder applied on a shutdown signal. `TerminalKitInput` already
had a `SignalHandler`, so it got wired — and the PTY probe said no.

| Configuration | Result on a real `SIGTERM` |
|---|---|
| no handler | killed by `SIGTERM` — dies, terminal **not** restored |
| `SignalHandler` installed | **ignores `SIGTERM`** — still running after 4 s, needs `SIGKILL` |

`DispatchSource.makeSignalSource(signal:queue:)` was given `.main`, and a terminal program blocks its
main thread in `read(into:)`. The main queue never turns, so the process stops responding entirely.

**The second time in this project that something returned successfully and did nothing**, after `ask`'s
own emulator harness reported PASS with every tier a no-op. Same shape: it reads as handled.

### Fixed in TerminalKit (ADR-0013), verified here

A `sigaction` handler writes one byte to a pipe and returns; a dedicated `Thread` drains it. Neither the
main thread nor a cooperative pool thread is involved. `onShutdown` reports which signal fired.

    SIGTERM: exit=143  raw-restored=True  alt-screen-left=True  cursor=True
    SIGINT : exit=130  raw-restored=True  alt-screen-left=True  cursor=True

**130 for SIGINT is what the old signature could not produce.** `onShutdown` carried no argument, so
`128 + signo` was unavailable and every shutdown would have reported the same code.

Roadmap 0006 is done. Both signals restore *and* die — the requirement, since a handler that restores and
swallows leaves a process that ignores `kill`.

## Two standards I had been following in name only

**`NSLock`.** I wrote it into two test helpers in this same session, having read TerminalKit's
`POSIXTerminalConnection` use `Mutex` for the identical job hours earlier. Replaced with `Mutex`, which
also removed the `@unchecked Sendable` — with a `Mutex` inside, the type is genuinely `Sendable` rather
than asserted to be.

**The macOS 26 floor.** I had been reading the primitive-replacement table as if the primitives were
unavailable. That table is the fallback for a floor *too low to permit them*. At this floor
`InlineArray`, `Span`, `RawSpan`, `Mutex` and `Atomic` all compile — probed, with the exact spellings,
because `RawSpan(_unsafeBytes:)` took four attempts and the compiler's note is what found it.

One negative result worth keeping: **`InlineArray` buys nothing in `ask` yet**, because
`writeContiguous` takes a `ContiguousArray` and the conversion allocates at the boundary anyway. Where
it pays is inside TerminalKit.

## The standards are now guards, not prose

`SourceStandards` scans each repository's own Swift and enforces: `NSLock`, `os_unfair_lock`,
`pthread_mutex` and `DispatchQueue` banned; `@unchecked Sendable` allowed **only** with a `SAFETY:`
comment; no `Task.yield` in tests; no `Task.sleep` unless the line names an injected clock.

Ported to both repositories. It found three `@unchecked Sendable` declarations in TerminalKit's `Rope`
that explained what the type *was* but never why it was safe to share — now annotated with the real
invariant for each.

Two bugs in the guard itself, found by running it: `@unchecked Sendable` was in the outright-banned
list *and* permitted conditionally below, which is two rules contradicting each other in one file; and
the `SAFETY:` search looked one line up, rejecting `POSIXTerminalConnection` whose note sits above a doc
comment. The search now walks the comment block — demanding one exact arrangement would enforce
formatting, not safety.

### Six probes, five of which were worthless

`NSLock`, `@unchecked Sendable` and `Task.yield` all caught in `ask`. In TerminalKit, `NSLock` and
`DispatchQueue` first reported **ESCAPED** — because `NSLock()` does not resolve in a file importing only
Darwin, so those runs were **build errors, not red tests**. With a violation that compiles: both CAUGHT.

**Fifth time this month a probe turned out incapable of failing.** That is now the dominant failure mode
of this project, and the reason every guard here is broken on purpose before it is trusted.

## The white paper, and what it cost to add two principles

At 197 of its 200-line cap, so the new standards had to displace something. Rewording could not do it:
the formatter re-wraps to its configured width and restored the count every time. **The cut had to be
content.**

The content was section 6, terminal doctrine — duplicated from TerminalKit and **wrong**. It asserted
DECSTR resets modes while preserving scrollback; TerminalKit measured that against four emulators and
DECSTR resets no DEC private mode (TerminalKit ADR-0002). A refuted claim, restated from a repository
that had already corrected it, sitting in a principles document.

Replaced with a pointer plus the shape of the mistake. 200 of 200 lines, and the budget test did its job
by refusing anything less honest.

## Budgets after the signal work

Re-measured on the shipping build, not the testable one: cold start 10.62 ms / 25, idle 5856 KiB / 8192,
input 0.11 ms / 2, action 0.04 ms / 2. All within. The cold-start figure swings between roughly 5 and
15 ms depending on machine load, which is exactly why the budget carries 2× headroom rather than sitting
on the measurement.
