## What the screen does that I noticed

- The status line's model label follows the **last request**, not the selection: right after `/model agy claude-sonnet-5-5-low` it still read `agy/gemini-3-flash` until the next turn. The
  notice "Model selected for this run: …" is what says the switch took, and the probe waits for that. Whether the other providers behave the same was not checked; this is an observation, not a
  claim of a defect.
- A slash command starts no turn, so a script that waits for "working…" after one waits forever. My first scripted run got ahead of the screen for that reason and typed prompts while a command picker
  was open; the screen queued them as steering, which is what a person typing fast would get.
- `pyte` has no scroll regions, so the emulated screen is garbled until a forced full repaint (the other probes do this too). Every check reads after one.
