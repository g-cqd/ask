## A real measurement-harness defect

The unchanged remote control failed to reach a prompt during a repeated A/B run. That run was rejected rather
than dropping the sample. Inspection found `measure-budgets.py` still resized the PTY in the parent **after**
`fork`, racing the child's first size read, unlike the already-correct action/cache harnesses.

A deterministic test replaced fork, ioctl and exec with recording doubles. Both assertions failed before the
fix: the child reached exec with no size call, and the parent called ioctl after fork. Moving the same 40×120
setup to fd 0 in the child, before exec, made both assertions pass. Setup failure is no longer swallowed.
This changes the measurement harness, not ask's runtime. Temporary check: `/tmp/ask-test-budget-pty.py`; the
contract is child ioctl-before-exec and no parent resize. Python syntax checks also pass.

The fix removes that race; it does **not** establish the cause of the remaining cold-start variability.
