# Diary — 2026-10-20 (28)

## Codex model discovery

Roadmap 0038, Codex slice. Worktree `ask-models`, branch `codex-model-catalog`, based on `cedd78d`.
The user authorized model discovery after their subscription refused a model listed in pi's static catalog.

### Endpoint probe, before implementation

Claim: `GET https://chatgpt.com/backend-api/codex/models` returns the account's live catalog with ask's existing
credentials and identity. Temporary `CodexCatalogProbe.liveCatalog` used `CredentialFile.standard`, `CodexAccess`
(including its locked refresh owner), `URLSessionTransport` and the existing bounded collecting reader. It did not
print credentials or inspect another CLI's credentials. Ran:

```sh
swift test -c release --enable-testable-imports --filter CodexCatalogProbe
```

**REFUTED without a version query**: HTTP 400, 209 bytes. The JSON error identifies missing query field `client_version`.
**CONFIRMED with `?client_version=0.163.0`** (the installed Codex CLI version): HTTP 200, 569148 bytes. Root key `models`,
nine model objects. The first two calls together took 0.571 seconds in the test runner; that is not a benchmark.
Raw responses are owner-only temporary probe files under `/tmp/ask-models-probe-{0,1}.json`, not committed artifacts.

The account's first entry is `gpt-6.1-sol`, priority 1, visibility `list`, `supported_in_api: true`, context window
500000 and maximum context window 872000. Two entries are `hide`; seven are `list`. `gpt-5.5` is absent. Reasoning
levels are objects with `effort` and `description`, not the string array assumed in pi-integrations. None of the nine
entries supplies `max_output_tokens`. Base instructions account for much of the response and will not be cached or
adopted as instructions. Normal context comes from `context_window`, not the larger opt-in `max_context_window`.

The version query is observed server behavior, not a claim that ask implements every feature of that Codex version.
The client continues to identify itself as ask. Availability and limits remain account-specific.

### Mistakes

- Queued the release build through Agora's work tool. Its supervisor is an x86_64 binary, so the build compiled for x86_64
  and began rebuilding every dependency; I waited two minutes before looking at the architecture. Cancelled (job-228),
  confirmed the processes ended and the shipping binary stayed arm64, then built natively. Lesson: check the
  architecture of whatever launches a build, and look at the first minute of output, not the end.
- The named-connections direction was drafted as roadmap entries 0045–0047 rather than an ADR, because nothing in it is
  decided by evidence yet. Several claims in 0046 (account chooser, older-writer compatibility, lock behaviour across
  processes) are open questions, written as such.
