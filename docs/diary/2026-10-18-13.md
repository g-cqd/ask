# Diary — 2026-10-18 (13)

## Production subprocess choice

The user called out `swiftlang/swift-subprocess`. Adopted in ADR-0011 and tool entry 0011, but no
unused package dependency added. Production child execution goes through an injected interface using
structured `Subprocess.run` lifetime, not a new Foundation.Process or raw spawn wrapper.

Apple-docs MCP lookup returned HTTP 530. Read the local official checkout's complete README and
manifest at `b3937ab85dd32f6e9435914599c1519074769c1a` (`1.0.0`) and Atelier's existing ProcessSession.
Its Swift 6.2/macOS 13 requirements fit our floor. This is inspection evidence, not an ask benchmark.

Important distinction: collected-output limits throw on overflow, whereas ask wants bounded head/tail
results with a recoverable full-output file. That requires streaming/draining plus disk ceilings, not
just setting `.string(limit:)` and calling it truncation. Teardown/process-group behavior must be
verified with integration fixtures before promising descendants are cleaned up.

Atelier already has a wrapper, but its actor, unstructured lifetime task and unbounded stream are
application policy, not code to copy into ask by default. Reuse the official primitive and its lessons;
put genuinely generic helpers in Aemi. Test/probe scripts are not production launchers.
