# Diary — 2026-10-20 (51)

## A tool's output folds to a line and opens on a click

The first fold in the screen (TerminalKit roadmap 0018, ask roadmap 0051). The pin moved to TerminalKit `ad1c072`, which makes
`FoldStore` `Equatable` so a transcript that holds one can still be compared.

### What was built

- **The screen now receives what a tool returned.** `ConversationUpdate.toolFinished` carries `output` (defaulted, so the other
  call sites are unchanged); the composition root passes `output.content`. A transcript keeps at most 400 lines of it and says how many
  were cut, so one huge output cannot make every frame slower.
- **A tool block with output is foldable and starts folded** (ADR-0046, `ui.tools`): `▸ bash ls ✓ · 3 lines`. Opened it is `▾ bash ls ✓`
  and the output below it, two columns in and dim. A tool with no output has nothing to fold and keeps the plain line. A running tool
  has no count yet.
- **A click on the header toggles it**; a click in the body does not (that is for selecting). **Ctrl+O** flips every tool block, for a
  keyboard and for the mouse being off, and a choice made by click gives way to it. State is the kit's `FoldStore`, per block with a
  default, inside the transcript so a change bumps that item's revision and only it is re-wrapped.
- **The reader stays put.** Scrolled back, toggling moves the view by as many lines as the block gained or lost, so the header stays on
  its row. At the bottom the view follows the end, as it does for streaming.
- **What is copied is what is shown.** A folded block copies as its placeholder line, an open one as the header and the output. A
  selection is cleared when a block folds, since positions inside the body stop existing.

### What was checked

| # | Claim | Evidence | Verdict |
|---|---|---|---|
| 1 | Folded by default, opens and closes on header clicks, body clicks do nothing | 16 tests | **CONFIRMED** |
| 2 | The header does not move when a block opens while scrolled back | the header's row before and after, open and closed | **CONFIRMED**; no compensation fails 2 checks |
| 3 | Ctrl+O never reaches the prompt | the editor's text after the key | **CONFIRMED** |
| 4 | A selection reads the placeholder, not the hidden body | a drag from a folded header into the next notice | **CONFIRMED** |
| 5 | The tests can fail | seven mutations | **ALL CAUGHT**, after redoing two |

### What went wrong

- **Two mutations proved nothing at first.** One did not apply (the formatter had reflowed the line, so the "mutated" run was the real
  code and passed), and one survived because my test selected only inside the header row, which never reaches the body. A test that
  selects across the folded block was added and kills it. The sixth and seventh bad mutations in this work.
- `.tool(name:summary:status:)` gained a field and broke one existing test pattern; every other use was inside `Transcript`.

### Not verified

- **The agent side.** `AgentConversation.update(for:)` lives in the executable, which has no test target, so passing the output
  through is one line nobody tests. A real run was not made.
- **No real terminal.** The glyphs `▸` and `▾` have the width the kit's table says; a drawn frame was not looked at.
- **Thinking blocks do not exist yet**: the agent does not send thinking to the screen, so only tool output folds. Long code blocks in
  assistant text (`ui.codeFoldLines`) and images are not folded either.
- **A double click on a header** toggles on its first click, so the word it then selects is in the changed layout.
- **`ui.tools` has no configuration key**; `ScreenOptions.foldTools` carries the default.
- Keyboard focus and a key to open one block (not all) are not designed.
