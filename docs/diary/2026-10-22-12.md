# Diary — 2026-10-22 (12)

## Long code folds inside the reply — roadmap 0051, ADR-0063

### What changed

- `CodeFence` finds CommonMark fences by hard line (backtick or tilde, three or more, same-character close, unclosed runs to the end).
  `ShownCode` replaces each folded long block with one placeholder line and records which display lines toggle which block.
- `Transcript+CodeFolds` keys each long block by `(item, fence ordinal)`; `ScreenComposer` draws the shown text and records the same
  text for selection. Click on the placeholder opens; click on the opening fence folds; Ctrl+G flips all; `ui.code` and
  `ui.codeFoldLines` configure it; the screen height caps the limit at half its rows. `/help` names Ctrl+G.
- `ui.images` is still refused: there is no image content in ask to fold.

### A performance regression, found and fixed before landing

The first version asked `String.contains` for ``` and `~~~` twice per layout, and laid the text out through two separate passes.
Same-machine A/B (`code/stream delta, 400-line reply`, no fences, one assistant message of ~25 KB): **424 → ~1,020 µs**. That is
2.4× on the streaming path, with identical allocations. It was fixed by a single byte pass (`mayContainFence`) and computing the shown
text once per layout. After the fix, interleaved, same binary harness, base then head, two rounds each:

| Benchmark (120×40, release) | Base p25/p50/p75 | Head p25/p50/p75 |
|---|---|---|
| stream delta, 400-line reply, **no fences** | 424–436 / 431–439 / 439–447 µs, 508 allocs | 440–441 / 445–453 / 453–465 µs, 508 allocs |
| stream delta, 400-line reply, 4 long folded fences | 424–436 / 429–438 / 438–449 µs, 508 allocs | 424–428 / 433 / 441–445 µs, **315** allocs |
| open every long block (head only) | — | 666–671 / 674–684 / 686–693 µs, 769 allocs |
| unchanged frame with folded blocks | 10–11 µs, 3 allocs | 10–11 µs, 3 allocs |
| existing `frame/120x40` keystroke / streamed line / full redraw | 33–34 / 84–86 / 872–891 µs | 32–33 / 83–85 / 872–881 µs |

The no-fence streamed delta is **3–4% slower** at p25 (about +15 µs), inside the 15% gate and without new allocations. The fenced
reply is no slower and allocates less, because the folded view lays out fewer lines. The machine was far from idle (one-minute load
averages between 16 and 191 across the runs, which are the reason every figure is interleaved base/head, not one before/after pair).
