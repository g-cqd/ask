# Diary — 2026-10-20 (33)

## A prototype screen, and a grammar for `/` and `@`

The owner asked how six terminal coding harnesses (opencode, Pi, Claude Code, Codex, Vibe, Antigravity) handle commands,
file references, skills, agents and tasks, and to show variants in throwaway terminals instead of describing them. This
is the record of that work. The outcomes are in roadmap 0048 (the input grammar) and an addendum to 0015 (what the
prototype showed about pixel chrome); the prototype is `docs/prototypes/ui-lab/lab.py`.

No ask code changed.

### What went wrong

- **Two of my scripted drives were mis-sequenced.** One typed `G` into the draft because the screen was already in browse
  mode; one `Read` ran in parallel with the crop it needed. Their screenshots are **not evidence** and none is cited above.
- **The machine was heavily loaded** (load average up to 344 from other sessions' builds). A burst of key presses outran the
  prototype once and left it in a state I had not asked for. I paced the keys and logged them, and the final captures were
  taken with the log matching the keys sent.
- **My first "PASS" was wrong twice for the wrong reason**: a test window that included transcript rows, and a fixture too
  short to scroll. Both were bugs in the test, found by reading the failure, not by loosening it.

### Not verified

- Any terminal other than kitty: the colour query, kitty graphics, and the `?2031` colour-scheme notification (parsed,
  never seen sent).
- That translucent terminals look right in the painted mode, beyond one screenshot.
- Anything about how a turn is drawn by the six harnesses: no prompt was sent to any of them.
- Session addressing: there is no transport, so only the routing indicator and the rules around it were prototyped.
