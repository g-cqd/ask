# Diary — 2026-10-20 (35)

## A prototype screen, and a grammar for `/` and `@`

The owner asked how six terminal coding harnesses (opencode, Pi, Claude Code, Codex, Vibe, Antigravity) handle commands,
file references, skills, agents and tasks, and to show variants in throwaway terminals instead of describing them. This
is the record of that work. The outcomes are in roadmap 0048 (the input grammar) and an addendum to 0015 (what the
prototype showed about pixel chrome); the prototype is `docs/prototypes/ui-lab/lab.py`.

No ask code changed.

this file, so it is restored here as 35, with the probes renumbered after the current end of the ledger.)

### What went wrong

- **Two of my scripted drives were mis-sequenced.** One typed `G` into the draft because the screen was already in browse
  mode; one `Read` ran in parallel with the crop it needed. Their screenshots are **not evidence** and none is cited above.

  taken with the log matching the keys sent.
- **My first "PASS" was wrong twice for the wrong reason**: a test window that included transcript rows, and a fixture too
  short to scroll. Both were bugs in the test, found by reading the failure, not by loosening it.

## Later still: one block model, tints, half-row padding, and quieter strokes

The owner pointed out that I had padded some blocks and not others (the input, thinking and the assistant's output
got none), asked for a specific tint per kind of block, said that margins and breathing room only take space from the
content, and then that strokes should be more subtle.

| # | Claim | Probe | Verdict |
|---|---|---|---|
| 136 | Every kind of block, and the input, gets the same padding inside its own tint | tests over the generated transcript for each padding value, and over the input in every bottom section | **CONFIRMED**; **negative controls**: the input without padding fails with `(1, 0, 2)`, thinking without padding with `('think', 1, 0, 0)`, thinking sharing the tool tint with the tint-per-kind test |
| 137 | The kinds have distinct tints, and text stays readable on every one | 120 palettes x accents x surfaces, contrast of text, accent and status colours against all eight backgrounds | **CONFIRMED after a real failure**: a yellow accent at strong surfaces made the user tint so bright that white text reached only 6.89:1. Tint strength is now capped |
| 138 | Full-row padding costs content space | counted real content rows at the tail of a 120 x 42 transcript | **CONFIRMED, and larger than expected**: 47% of the rows with one-row padding, against 100% with none |
| 139 | Half-row padding, shared between neighbours, recovers most of it | same count; layout test that exactly one boundary row sits between neighbours with the right tints | **CONFIRMED**: 61% (22 of 36 rows), and it needs no pixel support |
| 140 | Strokes can be quiet without vanishing | stroke levels checked against every tint; ordering test; a control with `subtle` as loud as `strong` | **CONFIRMED**: 1.85:1 against the page on the owner's terminal; every level guarantees a minimum against every tint (1.4:1 for subtle), and the worst case there was 1.52:1 |

### What went wrong

- **The first block model was not one model.** I padded user messages, then the agent group and the diff, and treated
  the rest as plain text. The owner saw it before any test did, because my tests only checked the blocks I had
  chosen. The tests now enumerate every kind.
- **I made padding look free.** A transcript of one-line blocks lost more than half its content to it, which I only
  found by measuring after the owner's remark about space.
- **The `assistant tint` control I first wrote was weak**: swapping in another distinct tint violates nothing. The real
  violation, two kinds sharing a tint, is the control that counts.
- **The push gate failed once on the build system** (`Unknown error parsing property list`) with the disk at 98%. It
  was SwiftPM state in my own worktree, not the change. I deleted that worktree's `.build` and re-ran the whole gate; I
  did not bypass it.
- **Two sessions took the same diary numbers twice.** Settled by keeping the other session's and moving mine.

### Not verified

Kitty only. The half-row boundary uses `▀` and `▄`, whose rendering in fonts that draw them with gaps is untested. On a
terminal with opacity, the half-row against the page uses the base colour explicitly. The owner is the only person who
has looked at any of it.
