# Diary — 2026-10-22 (2)

## Bring the real screen back to the owner's text-only hierarchy

The prototype's visual contract was already settled: terminal-default backgrounds, no leading bars or icons, hierarchy from spacing,
text and colour. The first interaction implementation had kept the old `›`, `▸`, `▾` and inverse status surface. This slice removes
those from the actual screen, not only from the prototype.

- User text starts at column zero, bold, with its existing blank separation. There is no marker to exclude from a selection.
- Thinking placeholders say `thinking · 2 lines`; tool placeholders say `read file ✓ · 1 line`. Open blocks keep a plain header and
  the body underneath. The existing trailing tool-status marks are unchanged; no disclosure glyph leads a block.
- Status text is dim on the terminal's default background. Only selected text is reversed. Padding always restores default blank cells.
- `/help` names Ctrl+T and Ctrl+O. Header clicks and the content provenance remain the same mechanisms as before.
- Screen probes and the action-budget observer were updated to the actual text, not weakened to accept both the old and new designs.
  The multiline regression now checks a contiguous four-line prompt, without the old marker or indentation.

### Budgets, including the failed run

An initial uncoordinated eight-run measurement returned action median **6.80 ms**, over the 5 ms target, with a 3.44–20.09 ms range.
The observed machine load was over 15 with several compiler processes active; that is context, not proof of the cause. That failed
measurement is not discarded or called a pass.

One capacity-controlled absolute-budget run through Agora (`job-232`, weight 10, 12 runs) then measured the same release binary:

| Cold start | 18.14 ms | 35.77 ms | 11.02–36.21 ms | 25 ms |

The job waited 12.5 s for capacity and ran 11.7 s. The scheduler recorded load 24.77 and 34% CPU idle at admission, and 56% idle over
the run. All four **median** budgets pass; tails still exceed some limits. These head measurements establish no before/after speedup,
and do not establish that removing a status background caused or cured latency.
