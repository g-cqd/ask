## The fix

Two changes, red first (the compaction tests and the shell refusal test were written, run, and observed
failing for the right reason before the implementation):

- A threshold compaction with nothing before the kept tail is a **no-op, not a failure**.
  `compactionDue` first asks `Compaction.hasContent(beforeTailIn:)`, a walk from the leaf that stops
  when the tail's bytes are filled (a new `SessionTree.walkFromLeaf` primitive — no branch copy, so
  the check before every request stays cheap); `compact` then settles the maybe exactly, skipping
  quietly when `cut` finds nothing. An explicit `/compact` still says so, and a full window still
  ends the run.
- The bash tool's refusal for a `shell` argument that is not a shell's absolute path now names where
  the command goes ("the command to run goes in `command`"), and the tool description says the same,
  because the on-device model read "Override with shell" as the command's home.

## Still owed, and not to be assumed

- The on-device model's own behaviour (claiming it cannot run Python, the CET/CEST confusion) is
  model quality, not ask's; not acted on.
- A conversation that outgrows the on-device tail compacts on nearly every turn once past it — by
  design for a 4k window, but never watched in a long real session.
