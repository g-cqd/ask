# Diary — 2026-10-18 (15)

## Session persistence, and the first probe of pi itself

`SessionLog` landed (478f20f): append-only JSON Lines, strict about damage. All 20 tests passed on the
first run, which made it the moment to suspect them. Two were weak:

- "deterministic snapshot" encoded twice in one process. That cannot fail. Replaced it with a literal of
  the exact wire bytes, which pins key order and the format version.
- the forward-leaf check was shadowed by the tree's own final-leaf check, so removing it changed nothing.
  A new test puts a leaf record *before* its entry, which only the mid-log check rejects.

After that, 11 of 11 compiling mutations were caught. The size gate then forced a complexity refactor of
`decode` (cyclomatic 12 → extracted `Replay`), and three mutations were re-run against the new shape.

## pi 1.3.0 loses data silently — measured

The user asked for a standing rule: fix mistakes found in pi, back them with tests. The obvious place to
look first was the behaviour just implemented, so I ran pi's own `parseSessionEntries` and
`buildContextEntries` under node against damaged input:

    torn final line -> parsed ids: ["s","a","b"]      (c silently gone)
    corrupt middle line -> parsed ids: ["s","a","c"]  (b silently gone)
    unknown leaf -> context ids: ["a","b"]            (silent fallback)
    missing parent -> context ids: ["c"]              (history truncated)

Source confirms it: `content.trim()`, then `catch { // Skip malformed lines }`, and
`leaf ??= entries[entries.length - 1]`.

That is probably deliberate best-effort recovery in pi, not a slip, and ADR-0012 says so. It still loses a
user's turns without telling them, which ask does not do. Each divergence is pinned by a test whose doc
comment starts `Diverges from pi 1.3.0 (ADR-0012)`; there are 8. The probe lives at
`Scripts/probe-pi-session-parsing.mjs` with `PI_VERSION` so it can be re-run when pi updates.

## The honest cost

Strictness means a corrupt session will not load in ask, where pi would load something. An explicit
recovery mode is owed (roadmap 0008): keep the readable prefix, report exactly what was discarded.
