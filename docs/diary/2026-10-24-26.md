## What was built

`JobWatchdog` (`AskTools`): the first job makes a pipe and starts `/bin/sh` on a thread of its own, in a session of its own, with the
pipe as stdin and nothing else inherited. A job writes `+PID` when its process starts and `-PID` when it ends. The kernel closes the
pipe when ask dies; the shell sees end of file and stops what is still listed. The write end never blocks and never signals; the same
thread that starts the shell reaps it. `Job` registers and releases; `JobTable` owns one watchdog. Nothing runs before the first job.

## What the probes and tests showed

- **The real binary (`Scripts/probe-job-watchdog.py`):** `ask -p` starts `sleep 300 & ... wait` as a job, the fake provider holds ask's
  next request, the probe sends SIGKILL to ask. The control (the previous binary) leaves the job running; this one has stopped it within
  a moment. 8 checks.
- **Mutants:** 25 compiling ones, all caught by a named assertion in the end; the path to that was not straight (next section).
- **Cost:** see ADR-0077's consequences. The first registration is 63 µs; nothing for sessions without jobs.

## Mistakes, in the order they happened

1. **Tests that sleep.** The gate has a rule against `Task.sleep` in tests and I had written five. Replaced by events: a wait on the
   watchdog's own state, kqueue `NOTE_EXIT` through `ProcessExit`, and `Printed`. The same rule is why `Job.swift` had to lose a line
   (it is at the 250 ceiling exactly).
2. **Tests that hang when what they test is broken.** An unbounded event wait (`Printed.seen()`, a protection wait) never returns when
   the watchdog does nothing, so the mutant run timed out and a timeout proves nothing. Fixed by waiting on something with its own
   deadline: the kqueue wait for the job's shell, and a bounded `waitForProtection(within:)`.
3. **A new helper that broke an old test.** The bounded wait started a timer task that kept the watchdog alive for ten seconds, so the
   "let go, its shell ends" test failed, and every mutant ran against that failing base looked caught. I noticed because six unrelated
   mutants were all caught by the same test. The timer holds the watchdog weakly now, and the six were redone.
4. **A flaky test explained, not retried.** One run in forty showed the shell with descriptors 3–6 open. A listing a moment later showed
   only 0–2: they were the shell's own start-up. The assertion became "an inheritable marker descriptor from the test is not in the
   shell", which is the property that matters; 40 runs, no failures. Another flake was a zombie visible between `NOTE_EXIT` and the
   reaping thread's `waitpid`; the deterministic event is the protection state, which is set after the reap.
5. **Test debris.** When a mutant hung the "watchdog stops reading" test, its process was killed while the shell was stopped with
   SIGSTOP; three stopped shells were left running. Cleared by hand; the test now ends the shell in a `defer`.
6. **Crashes are not mutation evidence.** The SIGPIPE mutant first "escaped" because it killed the test process, which my runner
   cannot tell from a pass; a test of the descriptor's flags now catches it by assertion.

## What is not covered

A SIGKILL in the milliseconds before the shell has started; the shell itself being killed; a background child that outlives its job's
shell (the same as before); the check that a failed write is reported is covered, the guard that stops a late start overwriting it is
not separately tested. The measurements were taken on a loaded host (load 6–10): the wall medians are noisy and are reported with
quartiles, and no budget in ADR-0016 is touched by this change.
