# Diary — 2026-10-24 (26)

## Word and line selection in the input — roadmap 0051, ADR-0077

### What changed

- A double click in the input takes a word, a triple click the hard line, using the kit's `ContentSelection.word` and `.line` over the draft
  as one block of hard lines. The result is an ordinary input selection.
- `dropSelections()` splits "forget the selections" from "forget the pointer", so clicks that change a selection do not reset click counting.

### Evidence

No frame-path code changed (pointer events only), so no benchmark was run.

Seven mutants were caught: a triple click taking a word, the first click of a double forgetting itself, the line index fixed to the first,
the cursor staying, the copy ignoring its setting, a tab counted as four cells, the click count ignored. The first run found the real
defect (clicks resetting the pointer recognizer, so no double click ever formed); two tests were weaker than they looked: a triple click on
a line that is one word passed with the word rule, and the "forgets itself" mutant needed a test of the *first* click, not the second.
