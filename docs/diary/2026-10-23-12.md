# Diary — 2026-10-23 (12)

## An alias that carries a thinking level (roadmap 0047)

Worktree `ask-alias-thinking`, branch `alias-thinking`, from `57eedaf`, rebased onto `3c68bf2`. No Agora. This was chosen because the
agy connector (0052) needs a policy decision about a locally discovered client secret before any code, and 0044 needs a browser
sign-in of a spare Claude grant.

## Findings

| Claim | Probe | Verdict |
|---|---|---|
| A version-1 reader would silently drop a level | Reading the format: the file is replaced whole on every change | **By construction**; so the version is derived, 2 only while a level exists, 1 otherwise |
| `--thinking` can be the alias command's option | `probe-connections.py` against the first build | **REFUTED**: output `work/think is gpt-6-sol.`, file without a level. The root command also owns `--thinking` and the parser handed it there without a word. Renamed `--thinking-level` |
| An unknown hand-edited level is harmless | Files with `"ultra"`, `"HIGH"`, `true`, `3`, `""` | Each makes the file damaged and untouched (5 cases) |
| The new level outranks files and not the run's say | Unit cases for default, file level, explicit file `default`, `ASK_THINKING`, `--thinking`; then the real binary's `ask config` | **CONFIRMED**: `thinking xhigh … [alias work/think]`; with `ASK_THINKING=low`: `low … [$ASK_THINKING]`; the same model typed directly: default |
| With no level left the file is readable by an older build | Remove the only level, read `version` | **CONFIRMED**: 1, and no `thinking` key |

An accident, recorded: while checking the first binary by hand I ran `ask connections alias work x gpt-6-sol --thinking xhigh`
against the **real** `work` connection instead of the probe's temporary directory. It created a real alias `x` (without a level,
because of the bug above). I removed it with `ask connections unalias work x` and read the real file: `{"aliases":{},"version":1}`,
mode 0600, as before. No credential was touched.

## Cost

Baseline is main at `3c68bf2`, built the same way: **11,106,272 B** against **11,132,080 B** (+25,808). Three alternating
`measure-budgets.py` rounds of 12 on a host at load ~5 (baseline/feature): cold start p50 13.0/12.3, 12.2/12.4, 12.6/12.5 ms; input
delay 0.26/0.23, 0.21/0.23, 0.20/0.24 ms; in-process action 3.29/2.63, 2.86/2.64, 2.89/(not shown, one p95 of 79 ms in that
round's cold start); all equal within the spread. Idle memory **9872/10000, 9888/10024, 9880/10008 KiB: about +130 KiB in every
round**. A first run at load 18–27 was discarded as unusable for everything but memory, which agreed (+144 to +168 KiB). The last
two features (replay, this one) each showed 100 to 170 KiB more resident memory for 20 to 26 KB more binary, which is out of
proportion to the code added; the cause was not investigated, and may be page-fault layout rather than anything either change
does at startup. Nothing here is on the startup path when no connection is named. No claim of zero cost.
