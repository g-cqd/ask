## Keyboard selection in the input — roadmap 0051, ADR-0078

### What changed

- Shift with Left, Right, Up, Down, Home or End extends a selection from the cursor's starting place; the move itself is the editor's own,
  with the display width, so wrapped rows work. `inputAnchor` remembers where it began.

### A bug in TerminalKit, found only by the real binary

The first real run did not select: the cursor moved, but nothing was highlighted. Hand-built `KeyEvent`s in the unit tests had Shift alone; the
real decoder gave Shift **and Alt and Super**. TerminalKit's `SequenceRouter` read the modifier of a legacy CSI key (`ESC [ 1 ; 2 C`) as a
number that started at 1 and had digits appended, so `2` became `12` (its diary 2026-10-24 (1)). Fixed there with 11 router cases (9 red
before the fix) and pushed as `c0be417`; ask's four manifests and lockfiles now pin it. Nothing in ask relied on the wrong values.
