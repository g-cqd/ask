## Benchmark graph blocker found while doing steering

Catching up with main's TerminalKit update exposed a separate defect: the shipping manifest pinned
`ac898fd` while `Benchmarks/Package.swift` still pinned `74719fb`. SwiftPM refused the graph with
"required using two different revision-based requirements", before any benchmark could run.
The separate benchmark package now pins the same revision, and its lockfile is resolved.

A new release test reads both manifests and requires equality. Before the fix it failed at the equality
assertion; after, the full gate passes. The targeted loop benchmark resolves and runs again:

`cd Benchmarks && BENCHMARK_DISABLE_JEMALLOC=1 swift package benchmark --target SessionFileBenchmarks --filter 'loop/one turn.*' --no-progress`

No shipping code changed. At this dependency revision, before steering, the wall-time p50 [p25–p75]
is 44 [38–55] µs fresh, 57 [53–65] µs at 50 turns, 246 [233–281] µs at 500. Two syscalls per turn.
These supersede the earlier-dependency measurements for the steering comparison.
The unfiltered benchmark run still has an unrelated stale `PipelineProbe` call to `RenderPipeline.draw`;
that failure is reported here, not repaired as part of the pin fix.
