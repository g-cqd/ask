## What was built

Typing `/` at the start of a prompt lists the commands above the prompt; typing filters (name prefix, then name contains, then
summary); Up and Down choose; **Enter and Tab insert the choice and never send it**; Escape closes it and keeps the text. It is
derived from the draft after every key, drawn in text only (a bold, coloured choice; nothing filled or marked), takes rows from the
transcript and never the last one, and is hidden by an approval question. Files: `CompletionTrigger`, `PickerRanking`,
`CompletionPicker`, `ScreenController+Picker`, `ScreenComposer+Picker`, plus small edits to `ScreenState`, `ScreenController`,
`ScreenComposer` and `PromptEditor`.

**Two departures from the prototype's letter, flagged for the owner (ADR-0067):** a name typed in full closes the list, so `/quit`
and Enter still runs it (otherwise every command costs two Enters and every script and probe that types a command breaks); and a
command is offered only as the first word, because that is where `SlashInput` makes it run, so `please /co` is not a command.

## What it costs (ADR-0016)

`Benchmarks/.../PickerBenchmarks.swift` uses public API only, so the identical code ran on a tree without the picker. Three interleaved
rounds per side, `BENCHMARK_DISABLE_JEMALLOC=1` (so allocation counts read zero and are **not** measured), wall-clock p50, a keystroke
plus a backspace:

| Case | Baseline | Picker, unguarded | Picker, guarded |
|---|---|---|---|
| empty draft | 667 ns | 1,041 ns (one run) | **791 ns** (+124 ns) |
| 100-line, 6 KB draft | 35 µs | **65 µs** | **35 µs** |
| a slash word with the list active (`/co`) | 709 ns | 24 µs | 23 µs |
| `Down` in an open list | 542 ns | 11 µs | 11 µs |
| frame with the list, 120x40 | 6.5 µs | 11 µs | 11 µs |

The first picker looked for a trigger after every key by walking the draft to the cursor. That doubled a keystroke in a long draft, so
a guard was added: a command word can only start a draft whose first non-blank character is `/`. It restores the 35 µs. An active list
costs about 11 µs per key, roughly 0.6% of the 2 ms input budget; it was **not** optimised (an index of pre-lowercased names would help
and was judged not worth the code). One single-run empty-draft figure of 1,916 ns was noise, which the interleaved rounds showed.

Shipping binary: 11,250,128 to 11,276,032 bytes (+25,904). `measure-budgets.py`, two interleaved rounds of 12: idle memory
9,176 / 9,168 to 9,200 / 9,200 KiB; input delay 0.25 / 0.25 to 0.36 / 0.21 ms; action 2.94 / 2.78 to 3.89 / 2.91 ms. Cold start had one
round at 21.79 ms beside 12.61, with the baseline at 12.4 both times, so a paired cohort followed: 80 interleaved launches of each, all
complete, **median difference -0.00 ms, the picker slower in 50% of pairs, CPU -0.07 ms**. Nothing in the picker runs at launch, and the
odd round was the host (diary 2026-10-22 (09)), not the code.

## Merging with the runners list (published while this was in review)

`ask-runners` published the runner count and its list, drawn **above** the status line, while the picker is **below** it, so the bottom
of the screen is now transcript, runners list, status line, picker, prompt. The rebase conflicted in exactly one place, the composer's
row arithmetic; it was resolved by budgeting the runners list first and the picker from what remains, not by choosing a side.

- The merged `compose` was over the 60-line function limit again, so the stack of rows under the transcript moved into one helper
  (`writeBottom`). It first built a temporary array per frame; since `compose` is the keystroke path it was rewritten as plain loops.
- Two new tests: both open together (runners, status, then the picker, then the prompt, cursor on the last row), and a sweep over every
  screen height from 12 to 30 with 0, 1, 5 and 9 runners asserting the transcript always keeps a row. One mutant of the picker's row
  budget **escaped and is equivalent today**: the caps (five runner rows, at most seven matches) leave room on the smallest screen that
  offers a picker, so the budget never binds. The sweep pins the invariant so a future change to either cap fails a test, not a terminal.
  The other combined-layout mutants (placement, stacking order, the cursor row) were caught.
- Two of my tests hard-coded the list of built-in commands, which broke when the runners work added `/tasks`; they now read
  `ScreenController.builtIn`.
- Re-measured on the merged tree against current `main`, three interleaved rounds, wall-clock p50: `frame/120x40 keystroke` 31 to 32 us
  and `frame/120x40 streamed line` 87 to 88 us (both inside the benchmark's 1 us resolution), the 6 KB draft +1 us, an empty draft
  +42 ns; with the list active the pair costs about 28 us, roughly 14 us a key. Thirteen real-binary suites (the runners probe included)
  pass on the merged shipping binary, and the picker probe's negative control still fails against the pre-change binary.

## Mistakes, kept

- **Not red first.** I wrote the tests before the implementation but ran them only after it, so I never saw them fail. The mutants are
  what stand in for that, and they found one real gap (above). One test was also wrong, not the code: a cursor at offset 3 in `/config`
  has typed `/co`, so the query is `co`.
- **`git checkout` on a file with uncommitted work.** To undo a mutant I ran it on `ScreenComposer.swift`, which restored the committed
  file and **discarded my own picker edits** in it. I noticed from the empty `git status`, re-applied them, and checked the diff matched.
  The mutation script restores by writing back a saved copy, which is safe; the manual shortcut was not.
- **Five invalid mutants** that did not compile (an unused variable, unreachable code); they prove nothing and were rewritten. One
  "escape" was a crash misread by my script as a miss, so the script now labels a crash as the weaker evidence it is. One real escape
  (a defensive loop in the width clipping) was **equivalent**: a test over every width from 1 to 60 showed `ColumnSlicer` never
  overshoots, so the dead loop was deleted.
- **My probe, not the picker.** It sent `co` as one chunk and snapshotted between frames, showing the status line twice. I first
  suspected the layout, reproduced it at unit level (one status line, correct), then in the real binary (correct), and concluded the
  emulator cannot apply the terminal's scroll-region diffs mid-frame. The probe now types one character per frame. A second probe
  assertion expected `/reload` for `/re`; the real first match is `/resume`.
- **The baseline was built while I was editing sources.** I checked it before trusting it: none of the picker strings are in it, and the
  probe's negative control (no list) is the real proof.
- **A 25-minute `sleep` was aborted**, which looked like a stall. The run had in fact finished. Poll in short steps.
- A code comment quoted benchmark numbers before I had measured them. They happened to match; the rule is to measure first.
- Gate findings fixed rather than accepted: `compose` grew to 63 lines (limit 60), so the picker's row logic moved into helpers; an unread
  `sigil` property was removed (code only tests use does not ship); test fixtures that repeated the `SlashCommand(...)` shape became a
  shared table helper.
