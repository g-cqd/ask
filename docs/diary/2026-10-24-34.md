## What was probed

- The report's reproduction was read before anything was changed: both tests wrap the failing expectation in `withKnownIssue`, so
  they pass today and fail once fixed, which is what makes them a regression test.
- The design question the report left open was whether to retry the save or to keep the rotated pair. A retry only helps when the lock
  frees up within it, and costs seconds when it does not; the next call is a free retry, and keeping the pair in memory also keeps
  the interactive session working in the meantime. `ClaudeAccess` is created once per provider and `CodexAccess` once per run, so a
  reference box shared by their copies has the lifetime it needs.

## What was built

`UnsavedRotation` (one generic box), and in each accessor: settle first (try to save what is held), use what is held while the file
cannot take it, hold the pair instead of throwing when the save fails, and refresh from the held token rather than the spent one.

## What the mutants found missing from my tests

Four escaped the first set of tests, and each pointed at a real gap, not a redundant line:

- **"The spent token is the one compared"** and **"a save is never forgotten"** survived because nothing refreshed a second time while a
  rotation was held and the save then succeeded. That only happens if the lock frees up in the middle of the second refresh, so a
  transport that lets go of the lock when the second request is sent now does it (`ReleaseOnSendTransport`). Both accessors.
- **"The held credentials are not used" (Codex)** survived because the Codex tests only ever released the lock before the second call.
  A test that keeps it held and checks that nothing is sent now covers it.
- A mutant that did not compile was rebuilt, and one runner script was regenerated after a regex substitution rewrote its escapes.

## What the gate found that I had not looked for

`CredentialRefreshRaceTests` had a test, "a refreshed pair that cannot be saved is reported and never used", pinning the opposite policy,
and roadmap 0045 stated it as a requirement ("failed persistence is reported before a refreshed token is used"). I had not searched for
it before changing the behaviour. Reading the reasoning, its premise is that the old file stays a usable sign-in, which is false once the
server has accepted a single-use refresh. The requirement is superseded explicitly (ADR-0082, a note in roadmap 0045, the test rewritten
and commented), not quietly overridden. The part of the old rule that was about not being silent is **not** provided: the providers have
no channel to the transcript, so the user is not told. `rotationIsUnsaved` is the hook for that, and it is owed.

## Not probed with the real binary

The token endpoint is a constant in the shipping code with no override, deliberately (a way to redirect a refresh token to another
server would be a hole), so a PTY probe cannot stand in a fake endpoint. The unit tests drive the real accessors, lock and file against a
scripted transport. The credential-related probe suites were run on the shipping binary for regressions only.

## Not covered

An ask that exits before any later call saves the held pair (a one-shot `-p` run whose save failed) still leaves the spent token in
the file. Closing that means writing the pair somewhere else, which is a second place for a secret and a decision of its own.
