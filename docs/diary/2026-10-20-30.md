### Mistakes

- First mutation round: one mutant **survived** (a refused save still created the directory and lock file) because the test only
  checked that `credentials.json` was absent; and two were compile errors (`if true` is a warning, warnings are errors) which
  prove nothing. The test now checks the directory, and the two were redone with mutations that compile. Rerun: all killed.
- Started the mutation driver with `setsid`, which macOS lacks; it never ran, so nothing was mutated. Found by reading the
  output instead of assuming it started.
- An earlier test of mine acquired a lock before the directory existed. The test was wrong; the finding was useful.

### Observations, not acted on

- ask retried a 429 "usage limit reached" four times with 1, 2, 4 and 8 s backoff. A quota that resets over hours is not
  transient on that scale. Follow-up for the retry policy, not changed here.
- `SessionLock` is not a duplicate owner of this concern: it binds to a session file's inode and never waits, because a
  session rewrite replaces the file; these locks live on side files that are never replaced.

### Not probed

  race is tested with two accesses and one transport, not two processes).
- That cancelling a lock wait closes its descriptor (the code does; no test pins it).
- Mixed old and new asks racing on a save: old ones do not take the save lock.
