# 2026-11-13 (05): every session format searchable; an encrypted session's index sealed (t209)

The owner chose an encrypted index beside encrypted sessions. Reading the file only worked for plain JSONL: compressed sessions were
not searchable either. So the index now reads the session's entries (`SessionRecorder.tree`, append-only: the index keeps their
count), whatever the format, and keeps one file `<session>.search`: the count and the AemiSearch snapshot, sealed with AES-GCM
(the file's name authenticated) under a key derived from the user key (`ask.search.v1`, as pictures use `ask.images.v1`) when the
session is encrypted; never written in the clear for one, kept in memory when no key is open. `/encrypt` removes a clear index;
the next search writes it sealed. A file that does not read is rebuilt from the entries.
