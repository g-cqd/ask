# 2026-11-15 (01): serve answers initialize, and the family's connection learns to serve

Roadmap 0234 step 2, the first step of the order of work: a spike that could fail. The owner's answer to the design was to go.

| Claim | Probe | Verdict |
|---|---|---|
| AemiJSONRPC builds inside ask under its strict flags, with AemiRuntime for the reader | a target `AskACP`, `swift build -c release --product ask` | **Holds** |
| `initialize` is answered as the specification's example is | seven tests against an in-memory client; red first, with a server that answered null | **Holds** |
| A real process does the same, and ends when its input does | `ask serve` over pipes, two requests, then the input closed | **Holds**: first answer in 10.5 ms, the second in 0.08 ms, exit 0, nothing on standard error, 12.6 MB resident |

| `LineFraming` has the limit flaw the fuzzer found in ask's `LineSplitter` | its source read, not run | **Open**, leaning no: it measures a line at its newline as well as while it waits. A fuzz target would settle it |

The fourth and fifth were put to the owner, who chose to fix them in AemiJSON. Done there, test-first (its roadmap 0011, its
diary of the same day): `JSONRPCConnection(serving:…admit:…)` calls `admit` on the reader for each request, in order, and runs
the work it returns in a child task; a serving connection answers an invalid body and an overlong line with their errors. Pushed
as AemiJSON `31ce461`. ask still pins `806b481d`: the pin moves with the family's repin, which is the owner's.

So what landed in ask uses the connection as it was: `AskACP` (`ACPServer`, `ACPRouter`, the three errors, a descriptor
sink), the hidden `ask serve`, and tests that send one request at a time and wait for its answer, since two at once would be
answered in either order. The first version of those tests fed `initialize` and another request together and passed by luck of
scheduling; found by the live probe, not by the tests.

Also decided by building: the front needs only AskTUI's `Conversation` protocol, the seam the screen drives the agent through,
so `AskACP` sits beside `AskSession`, not above it (ADR-0154).
