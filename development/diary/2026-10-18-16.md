# Diary — 2026-10-18 (16)

## "As convenient as pi, if not more"

The user ruled on strictness: ask must be at least as convenient as pi. A loader that refuses a corrupt
session fails that test however principled its reasons, so recovery became the default (ADR-0013) and
strict decoding became a wrapper over the same parser.

"At least as convenient" needed a baseline, so pi's file loader was run on real temp files before any code
(`Scripts/probe-pi-session-loading.mjs`). Three findings I had not expected:

    corrupt header -> loaded ids: []                          pi loses every intact message
    torn tail -> file modified by load: true                  pi writes during load
    torn tail -> file now ends with: "...{\"type\":\"message\",\"i\n"
    duplicate id -> context text: ["second"]                  last wins

The second is the sharpest: pi repairs an unterminated final line by appending a newline, which turns a
torn half-record into a permanent corrupt line that every later load silently skips. ask's loader is pure.

One more claim was probed instead of assumed: an off-branch compaction boundary. pi gives
`["c","after"]` — summary and later entries, everything before dropped. ask splices the compaction out and
keeps the raw messages.

## Implementation, and what the mutations said

A pure refactor first (`restore` as the tree's single incremental validation point), committed alone.
Then recovery, red first. 14 tests passed on the first run, so two untested branches were looked for and
found: a header that first appears after records, and a leaf record naming a spliced compaction. With
those added, 10 of 10 compiling mutations of the repair logic were caught, including "strict decode ignores
issues".

`select` had invented `EntryID("")` for a case that cannot occur. Replaced with an explicit branch.

## Records, not reports

The user ruled out filing anything to pi. Findings go to `docs/PI-FINDINGS.md`: eight rows, each with its
probe, plus one suspicion that running the code refuted. ADR-0012 is amended rather than rewritten; the
white paper and AGENTS.md say "recorded here, never filed upstream", and AGENTS.md adds the rule that a
divergence may be stricter about reporting, never about working.
