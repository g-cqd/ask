# Diary — 2026-10-27 (22)

## Mistral's reasoning models send content parts, not a string

`/model mistral zai-glm-5-3` failed on the first thinking chunk with "the
response stream broke the protocol: malformed". The OpenAI-compatible decoder
typed a delta's `content` as a string, and Mistral sends something else for
its reasoning models.

### The probe

Against `https://api.mistral.ai/v1/chat/completions` with the stored Vibe key
(`zai-glm-5-3`, `mistral-large-4`, `zai-glm-5-2`, `magistral-medium-latest`, and
a tool-call request; the two `zai-glm-5-3` captures are kept byte for byte in
`Tests/Fixtures/OpenAICompatible/mistral-glm53-*.sse`):

- `zai-glm-5-3` and `mistral-large-4` send a delta's `content` as a **list of
  parts**: `{"type":"text","text":…}` and
  `{"type":"thinking","thinking":[{"type":"text","text":…}],"closed":…}`.
  `closed` is present on some thinking parts and absent on others, and one
  part can carry several segments.
- Plain answers, and `zai-glm-5-2` on a trivial prompt, send strings as before.
- Tool calls keep the standard `tool_calls` shape (`index` a number,
  `function.arguments` a string); the final chunk carries `finish_reason` and
  `usage` as usual.
- Decoding `content: […]` as `String?` throws, which the decoder reports as
  `.malformed` — the error the run showed.

### The fix

`OpenAIWireChunk.Content` reads a delta's `content` as a string or a list of
parts; `text` parts join into text, `thinking` parts into reasoning, and a part
of an unknown type is ignored like any other unknown field. Red first: four
unit tests and three recorded-stream replays failed with `.malformed` before
the change; all pass after
(`swift test -c release --enable-testable-imports --filter 'OpenAIStream'`).

### Also learned

The Vibe-issued key answers `zai-glm-5-3`, and `/v1/models` lists the
`zai-glm-*` ids, so pi-integrations' `mistral-vibe` domain can offer the whole
Mistral catalog instead of only `mistral-large-4` (fixed in that repository in
the same session).
