# 2026-11-13 (16): the Keychain asked again and again: a test fixture had moved the person's credentials into it

The owner: "stop asking hundreds of times for access to the keychain". Their ask is ad-hoc signed, so by design (roadmap 0110) it
keeps secrets in the credential file and never touches the Keychain. Yet `~/.config/ask/credentials.json` held `ask:keychain`
markers and the login Keychain held its five records, created 2026-11-13 20:44:43 UTC: the first run of `AskSessionTests`.

| Claim | Probe | Verdict |
|---|---|---|
| The secrets were moved by a test, not by ask | the items' creation time is the first `ConversationFixture` run; the unified log shows `swiftpm-testing-helper` writing them | CONFIRMED |
| Why a test could: the fixture's environment had `HOME` but no `XDG_CONFIG_HOME`, and `CredentialFile.standard` takes the home from `NSHomeDirectory()` | read; the fixture now sets both XDG folders, and a test holds its files under its own root | fixed |
| Why it moved them: `runningBuildIsStablySigned` was true in the test host (signed by Apple), so `auto` chose the Keychain there | `CredentialStorageSigningTests`: red (4 expectations), green once the identifier must be ask's | fixed |
| The same made AskAITests leave items for temporary files in the login Keychain | 87 items under service `ask`, all for `…/T/ask-(shared, connections, claude-named, store, placement, binding)-UUID` | CONFIRMED |
| After the fix a full test run adds none | 87 before, 87 after; the real file keeps no marker | CONFIRMED |

## Repaired on this machine

- The five records put back into the credential file from the Keychain by the same test host that put them there (so nothing was
  asked), through `settleSecrets`, which reads each back before letting go; the Keychain's copies removed. `ask models` reads them
  without a prompt. A copy of the marker file is in `/tmp/credentials.markers.bak` (it holds no secret).
- The 87 leftover test items deleted from the login Keychain (all for temporary test files).
