## Mine

- A new thread event for the name would have made an older build fail to read the session: `ThreadRecord.Event(rawValue:)` throws on
  one it does not know. A rename under an id no thread has is read by every build.
- The first title went out from the screen's thread, right behind the first frame, and the gate hung in
  `RenderThreadScreenTests`: with a terminal slow to take that frame, the screen waited on it and handled no key. The title now goes
  from a thread of its own (`TabTitleWriter`; the sources ban `DispatchQueue`), in order; only the title given back on exit waits for
  it. The test passes again, and `TabTitleTests` holds a stuck terminal that `send` must not wait for.
- `deliver(_:to:)` and `compact(update:)` took a non-escaping `update`; naming after a compaction keeps it, so both now escape.
