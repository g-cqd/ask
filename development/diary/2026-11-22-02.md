The owner put 0209 before MDM (0130) on 2026-11-22. ADR-0166 chose AskCore for the shared value types.

| Claim | Probe | Verdict |
|---|---|---|

## The twins go

Ten `*Preference` enumerations and their screen twins became one type each in AskCore (`Dim`, `SessionTint`, `Appearance`,
`InterruptKeys`, `QueuedAfterInterrupt`, `TimeoutDisplay`, `NotifyStyle`, `StatusPathForm`, `StatusPathSide`, `SpinnerStyle`), the
screen's behaviour kept as extensions in AskTUI, which now imports AskCore (`check-layers.py`, the dependency audit). `RunSettings.word`
and the twin test went with the last twin. `SpinnerStyle` keeps `dot` and `star`, marked `isOnlyRead`, drawn as the default as before.
Each move was built and its suites run before its commit. dolly then saw `ConfigurationFile`'s and `UISection`'s field runs as one
structural clone (the type names now alike): accepted where it is.

## Step 2: one declaration per ui setting

`UISetting.all` holds, per key, its catalog row and three closures built from a key path: read from a file, write back as a file
writes it, layer. `UISection.keys`, `value(forKey:)`, `layered(with:)`, the `ui` decoding (with `fold`'s object) and `SettingCatalog.ui`
come from it. First, as its own behaviour change, `ask config` lists the `ui` keys in the catalog's order (red first: an order test).

| Claim | Probe | Verdict |
|---|---|---|
| Behaviour unchanged | AskAgentCoreTests (1,182) and AskSessionTests (90), `config.example.jsonc` compared by `SettingCatalogTests` | green |
| The step-1 gate still fires through the table | `tint`'s declaration pointed at `separator` | 9 issues |
| The cost | a throwaway benchmark, release, 31 samples of 200 parses of the example file, and of 2,000 layerings with one `value(forKey:)`; new and old interleaved, twice | parse: 93.3 and 92.8 µs new against 89.7 and 92.2 µs old (p50), about 1 to 4 %, near the noise; layering plus a lookup: 167 and 153 ns against 111 and 116 ns. Paid once per configuration load: kept |

Not done: the memberwise `UISection.init` and its `@dl:accept` comments (8 in UISection, 15 in ConfigurationFile, against "fewer than
five"); the other sections' declarations, with their merge rules, which MDM needs; adding a setting is now its field, its declaration and
its screen option, plus the docs sentence.

## Every section but mcp and the top-level keys declared, each key with its merge rule

`UISetting` became `SettingDeclaration<Section>`, carrying `SettingMerge` (`replaces`, `adds`, `narrows`); a section's `SettingTable` and the
`DeclaredSection` protocol give it reading by name, `value(forKey:)`, `layered(with:)` and its description. Declared, one commit each:
`ui`, `hooks`, `agents`, `jobs`, `skills`, `threads`, `environment`, `sandbox`, `openers`, `approvals`. One generic
`ConfigurationFile.SectionDecoded<Section>` replaced nine hand-written decoders (a key holding an object of settings, `ui.fold`, read key by
key; a retired key, `threads.merge`, read and ignored). One behaviour change, apart: `ask config` lists `threads` keys in the catalog's
order (red first).

| Claim | Probe | Verdict |
|---|---|---|
| Behaviour unchanged, each step | AskAgentCoreTests (1,182), AskSessionTests, the section's own suites, after each commit | green |
| The per-key test covers every declared section, and fires | `hooks.checkTimeout` declared on `maxContinues` | 2 issues |
| The rules are guarded by tests | `environment`'s addition replaced by a replace; `sandbox.network` taking the later level; `sandbox.hide` replaced | each fails an existing test (EnvironmentSectionTests, SandboxStrictConfigurationTests, SandboxConfigurationTests) |
| The decoder's special cases are guarded | the retired-key branch removed; the nested-object branch removed | ThreadsSectionTests fails; ten tests fail. A first "survivor" was a mutation that never applied: the formatter had reflowed the line the edit looked for (checked by counting the edit's matches since) |
| A plain `init()` beside a defaulted one is not ambiguous | `/tmp/initprobe.swift` | `S()` takes `init()`; but a public default argument then names it, so `ApprovalsSection.init()` is public |
| dolly under `--strict` | `.ci/swift-ci run quality` | clean, after removing the clones the tables exposed rather than accepting them |

Cold start, measured interleaved when the install was refused (13:36): new 51.8, 64.7, 57.7 ms against the installed 67.2, 53.9, 76.2 ms
(medians of 12): no regression, and both over 50 ms on this machine at that hour.

Left for 0209: `mcp` (servers by name, masks) and the top-level keys; the memberwise `UISection.init` and its `@dl:accept` comments.
