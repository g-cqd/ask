## Implementation evidence

Red first: 10 assertion failures against API-only stubs. Then tests across the encoder and the client over the observed
refusal body: order and window of replay, text before reasoning, every unreplayable signature, an edited session, one retry
without reasoning, notice before the answer, gate memory, no retry for another refusal, no retry after events were delivered,
no retry for a request without reasoning, the refusal as a first stream event, a refusal after a delivered event, and the kind
decoded from the code.

**A correction to my own mutation run.** The first 20-fault run reported 20 killed, and it proved nothing: I had added the
"refusal after delivered events" test after the last unmutated run, it failed on its own (a single network read buffers the start
event, so nothing had been delivered and a retry was correct), and a baseline with one failing test makes every mutant look
killed. The full gate caught the failing test. The driver now runs the unmutated suite first and stops unless it is green. The
rerun against a proven-green baseline found **one survivor**: removing the `type == "reasoning"` check, because my edited-session
cases lacked sealed content and the other check covered for it. Two cases with sealed content and the wrong type
(`function_call`, `message`) were added; all **20 faults are now killed**, restoration verified by hashes. The corrected test
delivers the start and the refusal in two reads. Earlier first attempts that did not compile or match text (an unused variable,
an unused set, and a mutation whose text no longer matched after formatting) were also redone. The analyzer found `isContextOverflow`
and the new predicate duplicating one unpacking; the shared `reportedKind` replaced both, and two mutations on it were killed.
The structure gate caught `AgentConversation.swift` at 251 lines (the notice case pushed it over); its event mapping moved to
`AgentConversation+Update.swift`.

Two things deliberately not claimed: `CodexProvider` holds the gate and sits in the executable target, so its wiring is verified
only by the live run; and `ModelEvent.notice` reaching the screen and `--print` has no unit test.

Probe mistakes, kept: a first compile failed the 500 ms type-check limit on a six-term product (replaced by a constant); a stray
brace from a scripted edit; and I once ran `swift build --build-tests`, the form AGENTS.md says cannot resolve `@testable`, so its
error was not evidence about the code.

## Verification and cost

Full gate `Scripts/quality.sh --check`: swift-format, SwiftLint, analyzers, measurement guards, **1218 tests** (87 + 169 + 67 +
337 + 558). Executable probes on the final shipping binary: probe-thinking (19 checks), model-lists, quota and agent-run, all
exit 0. Live `ask --print` on the final binary, two more interleaved pairs: no fallback notice, correct, 11.1 s and 11.3 s against
23.8 s and 14.6 s without replay.

Baseline for cost is main at `2a2df31` (the commit this branch is rebased onto), built the same way: **11,073,696 B** against
**11,094,240 B** (+20,544). Three alternating `measure-budgets.py` rounds of 12 on a quiet host (load ~2.5), baseline/feature:
cold start p50 26.1/26.7, 25.8/25.5, 25.6/24.9 ms (equal; both sit at the 25 ms limit under the harness another agent changed
to report the starting core, so that is not this change); idle memory 9856/9960, 9856/9960, 9856/9936 KiB (**about +100 KiB,
every round**); in-process action 4.28/3.84, 3.61/3.97, 3.77/3.92 ms (mixed, no direction); input delay 0.55/0.66, 0.57/0.65,
0.57/0.67 ms (**+0.08 to +0.11 ms in all three rounds, within the 2 ms budget, unexplained**: nothing changed here touches input
handling, and a 20 KB larger binary is a possible but unmeasured layout effect). An earlier comparison against an older binary
mixed this change with other agents' commits and was discarded. No latency claim is made for the app; the measured gain is
a Codex model's step time where it reasons.
