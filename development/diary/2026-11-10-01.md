# 2026-11-10 (01): resume arguments are not filesystem paths (n54, t247)

## Claim: path display resolves flags against the working directory

- **Probe:** `swiftc -O Sources/AskAgentCore/Session/PathDisplay.swift /tmp/ask-resume-cause.swift -o /tmp/ask-resume-cause && /tmp/ask-resume-cause`.
  The small main calls `PathDisplay.shellArgument` on the reported flags and values, with `home` set to
  `FileManager.default.currentDirectoryPath`; no process directory or environment is changed.
- **Verdict: CONFIRMED.** `--thinking` became `~/--thinking`, `high` became `~/high`, and an empty argument became `~`.
  `shellArgument` calls `tilde`, whose URL-based symlink fallback interprets relative strings as paths against cwd.
  When cwd is under home, that fallback returns a home-relative absolute path, not the original argument.
- **Regression:** `PathDisplayTests` exercises the reported flags, provider/model values, relative and tilde paths,
  empty input and shell metacharacters, with cwd as its supplied home. This avoids changing global cwd in a test.
- The correction is to reserve path canonicalisation for absolute paths. Relative inputs stay written as they came;
  shell escaping still runs. Absolute paths retain home shortening and symlink handling.
