## Phase 2a: what is required holds while ask runs

The loader records each key a requirement sets, written in full (`model`, `ui.tint`, `mcp.docs`); `Configuration.requirement(of:)`
answers for a key or any key above it. `/model` and `/thinking` refuse a required key; a resumed session's recorded model gives way to
a required one, with a detail line; `/config` shows a required row as not editable, names it, and refuses to save it.

| Claim | Probe | Verdict |
|---|---|---|
| Each key a requirement sets is recorded, defaults' are not, a key above counts | `ManagedConfigurationTests` | holds; without recording, 6 issues |
| A model chosen for one run does not replace a required one | `applying(selectedProvider:model:command:)` | holds; without the guard, 1 issue |
| `/model`, `/thinking` and `/config` refuse, with the document named | `ManagedCommandsTests`, the conversation fixture with keys marked required | holds; each guard removed in turn fails it (2, 1, 1, 1 issues) |

Not tested on its own: the resumed session's detail line (its rule is `applying(selectedProvider:)`'s, which is). Phase 2b next:
managed-only keys.
