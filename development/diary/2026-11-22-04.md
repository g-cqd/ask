## Phase 2a: what is required holds while ask runs

The loader records each key a requirement sets, written in full (`model`, `ui.tint`, `mcp.docs`); `Configuration.requirement(of:)`
answers for a key or any key above it. `/model` and `/thinking` refuse a required key; a resumed session's recorded model gives way to
a required one, with a detail line; `/config` shows a required row as not editable, names it, and refuses to save it.

| Claim | Probe | Verdict |
|---|---|---|
| Each key a requirement sets is recorded, defaults' are not, a key above counts | `ManagedConfigurationTests` | holds; without recording, 6 issues |
| A model chosen for one run does not replace a required one | `applying(selectedProvider:model:command:)` | holds; without the guard, 1 issue |
| `/model`, `/thinking` and `/config` refuse, with the document named | `ManagedCommandsTests`, the conversation fixture with keys marked required | holds; each guard removed in turn fails it (2, 1, 1, 1 issues) |

Not tested on its own: the resumed session's detail line (its rule is `applying(selectedProvider:)`'s, which is). Phase 2b next:
managed-only keys.

## Phase 2b: `policy`, an organisation's alone

`policy.allowNoSandbox`, `allowYes`, `providers`, `models` (`*` matching any run of characters), only in `requirements.json`: any
other file that sets `policy` stops the load. Checked in `ConfigurationSource.load` against the flags and the model the run resolved
to, so `/model`, which loads again, is refused the same way. Between the organisation's own documents a later one replaces a key, as for
every other key: intersecting allowlists entry by entry was the first idea, and wrong (`claude-*` and `claude-opus-*` share no entry).
The rows sit in `SettingCatalog.managedOnly`, apart from what a person may set (the example file, the `/config` editor).

| Claim | Probe | Verdict |
|---|---|---|
| `*` matches any run, an empty list allows nothing | `PolicySectionTests` | holds |
| Only the organisation's requirements may set it, and a later drop-in replaces | the person's file, a managed default, then requirements and a drop-in | refused, refused, read; with the refusal removed, 2 issues |
| A run the policy does not allow does not start, named; one it allows does | `ManagedPolicyTests`: `--no-sandbox` under `allowNoSandbox: false`; `claude-test-1` under `models: ["gpt-*"]` | holds; with the check in `load` removed, 2 issues |

## `policy.mcpServers`

An allowlist of what a server is, not what a person calls it: its URL, or its command and arguments joined by blanks, `*` matching
anything. Applied once, at the end of a load, so every place that hands servers to the hub sees the result; `/mcp` cannot switch a
server on at run time (it signs in and reports), so a server switched off stays off.

| Claim | Probe | Verdict |
|---|---|---|
| A server is judged by what it is: two allowed (a URL, a command), two not (another host; a renamed command) | `PolicySectionTests` | holds, two notices; without the loader's step, 3 issues |
| No policy, every server as configured | the same files without `requirements.json` | holds |
