# 2026-11-22 (4): the managed layer, phase 1 (roadmap 0130, ADR-0168)

`requirements.json` and `defaults.json` (with `.d` drop-ins) in `/Library/Application Support/ask` (`/etc/ask` elsewhere), each a
`config.json`; defaults apply first, requirements last, each key by its declared rule; a document not root's, writable by others, or
invalid stops the load, named; a key they set shows "required by your organisation" or "your organisation's default".

| Claim | Probe | Verdict |
|---|---|---|
| Applying requirements last locks every kind of key | `ManagedConfigurationTests`: a required model over the person's file and `--model`; a required write scope and network over `--write anywhere` and `--network any`; a required `withhold` beside the person's | holds; with requirements applied before the person's file instead, 5 issues |
| A stricter value from below still counts where the rule narrows | a person's `network: none` under a required `provider` | holds (`none`) |
| Drop-ins apply after the main document, by name | `10-first`, `20-second` written out of order | holds |
| A document others may write, or someone else's, stops the load | mode 0666; an owner other than the one trusted | `.untrusted`, naming the document; with the check removed, 3 issues |
| A link is judged by where it leads | a link in the managed folder to a file in a folder anyone may write | refused; judging the link itself instead, 1 issue |
| A document that does not parse, or names an unknown key, stops the load named | `defaults.d/10-team.json` | holds |
| A connection's alias may change a managed default's thinking, never a requirement's | `applying(aliasThinking:)` over each | holds; treating both alike, 1 issue |
| No folder costs nothing worth naming | a throwaway benchmark, release, 31 samples of 200 loads of both kinds against the absent system folder | 10.5 µs p50 (p10 10.2, p90 12.2) |

Not verified: a real root-owned folder on this Mac (`sudo` was not used), and ask's message at start in a terminal when a managed
document is refused (the error is the loader's; startup surfaces a `ConfigurationError` as it does for the person's file).
