# 2026-11-14 (04): fuzzing the byte parsers, and where idle memory goes

Roadmap 0232, engineering plan phase E. Step 1 (fuzzing) is built and found four defects in its first ten minutes. Step 2 (memory)
is measured only: what would bring it under budget is a decision, not a fix.

## Fuzzing

| Claim | Probe | Verdict |
|---|---|---|
| libFuzzer works with the swift.org toolchain on macOS | a target with a planted crash (`bytes == "ask!"` traps), `-sanitize=fuzzer` | **Holds**: found in 20 s. Xcode's toolchain has no libFuzzer; swiftly's does |
| `swift build --sanitize fuzzer` over the whole graph is the way | ran it on ask | **Fails**: the macro host's swift-syntax, instrumented, was still building after 30 minutes |
| Instrumenting ask's modules alone is enough to guide it | `ASK_FUZZ=1` adds `-sanitize=fuzzer -enable-testing` to ask's targets; a separate package (`Fuzz/`) links them | **Holds** for ask's code (coverage 1,000–1,300 edges on `sse`, `session`, `text`). AemiJSON, AemiSearch and TerminalKit are not instrumented: `index` (23 edges) and the terminal's `SequenceRouter` (99) run blind |
| The harness can fail | the four findings below | **Holds** |

One executable, `ask-fuzz`, its target chosen by `ASK_FUZZ_TARGET`: `sse` (the decoder, then each provider's event decoder),
`session` (`SessionLog.recover` over plain and framed files), `mcp` (`LineSplitter`, then the message decoder), `terminal`
(TerminalKit's input router), `index` (a serialized search index), `text` (the small parsers and the guards of ADR-0150). Each
checks what the code promises, not only that it does not trap: the same events however the stream is cut, recovery that never
writes, untrusted text that stays in its section. `Scripts/fuzz.sh SECONDS [TARGET…]` builds and runs them side by side;
`.github/workflows/fuzz.yml` runs ten minutes each on Tuesdays, keeps the corpus, uploads a finding and opens an issue.

The rule: **a finding becomes a red test, then its fix, then a seed** (`Fuzz/Seeds/<target>/found-…`), so the next run starts from it.

| Found | Was | Now |
|---|---|---|
| `LineSplitter` (MCP stdio) | the length limit applied only to a line still waiting for its end: an over-long line was refused in pieces and accepted whole, or when its end came with its last piece | measured at its newline too; refused the same three ways |
| `SSEDecoder` | the same shape: only a line the network cut was measured, so a long line that was not `data` passed whole and failed in pieces | a line is measured, with its event's data, at its end and while carried. The `data` guard it makes unreachable is gone. A `data` line's ceiling is 5 bytes lower (the line, not the value) |
| `ForgeReferences` state | the one field of the first line not made one line: a state with newlines could start a section | one line |
| `ForgeReferences` address | has a line of its own, so `--- end of #7 ---` as an address read as the marker | through `UntrustedText.insideAttachment` |

All four were red before their fix (`LineSplitterTests`, `SSEDecoderTests`, `ForgeReferencesTests`). The two forge ones need GitHub
to answer with such a state or address, which it does not today: the guard is there because ADR-0150 says the text is not trusted.
After the fixes, 300 s of all six: clean (1.2 to 36 million runs each).

Not done: Aemi's and TerminalKit's own code is not instrumented, so their parsers are exercised, not explored; that belongs in
their repositories. `Fuzz/Package.swift` repeats ask's three pins: when ask moves one, the fuzz build fails until it follows.

## Idle memory: measured, not changed

The budget is resident size (ADR-0122): 15 MiB idle. On this machine an idle ask is 17.3–17.9 MB resident; its physical footprint
(what it dirtied) is 5.6 MB.

| Claim | Probe | Verdict |
|---|---|---|
| Idle ask holds a network stack | `/usr/bin/sample` of an idle ask | **Fails**: 11 threads, none in CFNetwork; the binaries are mapped, not running |
| The heap is the excess | `vmmap`, `heap` | **Fails**: 0.75 MB live in 3.2 MB resident (two screen buffers of 128 KiB are the largest); the rest is shared library pages |
| Returning free pages helps | `malloc_zone_pressure_relief` through lldb | **Fails**: 0 bytes freed |
| Linking a framework costs resident memory before any call | programs that link one framework and sleep, `ps rss` | **Holds**: Foundation alone 5.66 MB; +AppKit 6.58; +PDFKit 6.66; +AVFoundation 6.59; **+FoundationModels 8.30**; all four 8.78 (659 mapped images against 399). ImageIO, CryptoKit, Network and Security: nothing |

So about 3.1 MB of the idle figure is the cost of linking AppKit, PDFKit and AVFoundation (0.9 MB together: the pasteboard and
link opener, the PDF reader, the video reader) and FoundationModels (2.6 MB: the Apple on-device model). Getting under 15 MiB means
not loading them at launch: `dlopen` on first use for the first three, a helper process or a lazily loaded library for the model.
Or the budget changes. That is the owner's choice, asked, not taken.
