## Claim: a path whose `:line` wraps onto the next row loses it

**CONFIRMED, and wider than I had written.** `WrappedLinkPlaceTests` at 44, 50, 52 and 56 columns, in a reply, a notice and a tool's
output: every width that wraps failed, in all three. At 44 columns a tool's output linked the path as two pieces, each naming a file that
is not there: a defect the roadmap had not recorded. 56 columns, which does not wrap, passed.

- Replies and notices: the hook finds the path in the whole text, so the place rides on its address (`#L12C5`) until a link is made
  from it; `PathLinks.Link(columns:carrying:)` takes it off, so the terminal is still given the file alone.
- Plain rows (tool output, a notice with no project): the rows one hard line was wrapped into are linked as that line, the dropped
  space put back, and each link cut at the rows' edges.
- One pinned digest moved, Markdown off. A throwaway test compared old and new linking over its corpus: 230 rows' links changed, each a
  link reaching its row's edge; no text, style or source changed. Re-pinned with that said.
