## What still belongs to the process, and stops two sessions sharing one

Found by reading for static state, not changed here:

- **`SessionTasks`**: one task board and one list of notes for the process, following "the session in use". Two served sessions
  would write each other's tasks. 27 uses; it has to become the conversation's.
- **`SessionSearch.open`**, **`ProviderAccess.state`**: keyed by path or by target, so probably shareable as they are. Not probed.
- **`SessionKeyAccess`**, **`CredentialPlacement`**: the person's keys, one person: shared on purpose.
- **`JobTable`**, the MCP hub: made per run by `runInteractive`; a served session makes its own the same way.

So the next step before `session/new` is `SessionTasks` per conversation.
