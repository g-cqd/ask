## The fix, measured first

On this disk, a replace of a 2 KB file: 0.105 ms with no flush, 0.12 ms with `fsync`, 0.47 ms with `F_BARRIERFSYNC` on the file and the
folder, 6.0 ms with `F_FULLFSYNC`. `fsync` is nearly free and nearly useless here (macOS does not make the drive order writes), the full
flush alone exceeds the 5 ms action budget, and the barrier is what sessions already use (ADR-0017): so the barrier, before the rename
and on the folder after, for about 0.35 ms.

`FileFlush.barrier` (in `AskAI`, which depends on nothing else) is `AemiIO`'s `.barrier` with its fallback. `AtomicFile` flushes the file
with it and then the folder; `ProjectTrust`, which flushed nothing and kept its own copy of the same idea, now uses `AtomicFile`;
`ScopedFile.write` flushes the file before `renameat` and the directory after. Each takes the flush as a parameter that only tests give.
