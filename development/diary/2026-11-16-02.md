## Python: the profile is the wall

A JavaScriptCore context has nothing in it but what it is handed. Python has files, sockets and other programs, so for Python
"a script's only capability is the tools" is the profile its process runs under. Probes, on Homebrew's 3.14 unless said
(`development/research/probes/codemode/python-*.py.txt`):

| Claim | Probe | Verdict |
|---|---|---|

## Found: a result longer than a line of the wire was dropped

The Python test of the output limit hung for two minutes. So did the same script in JavaScript, once tried: a script's result
crosses to its keeper as one line, AemiJSONRPC takes lines of 8 MiB, and the limits copied from pi (16 Mi characters, 100,000
items) allowed 16 MiB and more. The connection dropped the line, answered the child with an error it does not read, and the
script "ran past its deadline" with its answer already given.

| Claim | Probe | Verdict |
|---|---|---|
| A result past 8 MiB is lost | `text` of 16 Mi characters through the keeper, both languages | **Holds** before: the deadline, 120 s later |
| The new limits fit whatever a script says | the worst case: a megabyte of control characters, six bytes each on the wire; 10,000 empty items | **Holds**: both come back whole, in both languages |
| A line too long still cannot hang a script | a child that sends 8 MiB and a byte | **Holds** after: fails at once, "The script's result is too large to return." Before: the test's time limit |

Changed: a script may say 1 Mi characters in 10,000 items (ADR-0156 amended), and the keeper ends a script whose child sends
a line the connection would drop.

## Known

- One Python allocation larger than the limit is made before it is seen (above). The keeper watching from outside would see
  it sooner; not built.
- A Python script that waits on what nothing settles waits for its deadline: Python has timers, so "nothing is pending" does
  not mean "nothing can come", as it does in JavaScript.
- The first Python script of a session costs one more start of the interpreter, to ask it where it is.
- The profile is not applied where `sandbox-exec` cannot be: inside another sandbox the child does not start, and the tool
  says it could not start the process.
