# Diary — 2026-10-19 (01)

## Sandboxing, probed before designed

The user asked for sandboxing as separate capabilities (network, read and write, by path), at any layer
from ask itself down to one tool call, with the model able to propose it per call or globally.
ADR-0020 decides it. Roadmap 0017–0022 slice it.

## What the probes established (macOS 27.2)

- `sandbox-exec` ships but is DEPRECATED. `sandbox_init*` are exported.
- Seatbelt enforces:
  - no network (even DNS), or localhost only;
  - writes confined to a path;
  - reads denied by path;
  - children inherit.
- **Profiles do not nest** (exit 71, via `sandbox-exec` and `sandbox_init` alike). This decided the shape:
  ask stays the unsandboxed supervisor by default, and each child gets one profile, the intersection of
  every layer. "ask started sandboxed" remains possible, with the stated cost that per-call Seatbelt is then
  impossible.
- `-D` parameters are injection-safe. Profile paths must be canonical (`/tmp` ≠ `/private/tmp`), failing
  closed.
- A sandboxed spawn costs about +7 ms (9.55 against 2.56 ms p50).
- I could not get Seatbelt's own denial records for these probes from the unified log, with or without
  `(with report)` / `(debug deny)`. Claude Code reads them somehow; open question, with a fallback.

## Read from installed binaries, not docs

- Codex: deny-default base policy, three modes, `sandbox-exec` around each command.
- Claude Code: a domain proxy, per-command escape hatches behind a permission gate, violations fed to the
  model.

Both keep the agent unsandboxed and sandbox its children, which matches the nesting rule.

`development/research/probe-seatbelt.sh` re-runs the claims. A failing probe on a new macOS is a release blocker
for the sandbox, never a silent downgrade.
