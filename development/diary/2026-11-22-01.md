# 2026-11-22 (1): a copied file pastes as its path; what a managed Mac gives ask

The owner, 2026-11-21: pasting a document copied outside ask or Sunset "always paste the last component of the path of the file";
and ask's configuration should be "mdm compatible", the most tunable of the coding harnesses.

## Paste (commit 64db8b41)

| Claim | Probe | Verdict |
|---|---|---|
| Ctrl+V of a Finder copy read the file's icon or its name | three `HostPasteboardTests` on a private pasteboard holding what Finder writes (file URL, name as text, a TIFF), run on main | **Holds**: all three failed (`.picture` came back) |
| Reading the file URLs first fixes it, pictures still attached | the same tests after the change; the Paste, Clipboard and documentation suites | green |
| A Finder copy really holds a TIFF icon | not probed: Finder's types were not dumped on this Mac (needs a person's ⌘C) | open |

Sunset's own Paste had the same fault and the same fix (Sunset 5f640e0, its diary 2026-11-22-01). A terminal that pastes ⌘V itself
(kitty, Terminal.app) still decides what it pastes; ask's Ctrl+V reads the pasteboard in every terminal.
