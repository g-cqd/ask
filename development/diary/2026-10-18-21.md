# Diary — 2026-10-18 (21)

## The Claude path, from bytes to `ask -p`

Eight layers landed in AskAI, each red-first, each mutation-checked, and pushed one at a time:
1. assembler;
2. request encoder;
3. PKCE/URL/paste;
4. token handling;
5. HTTP transport;
6. credential file;
7. auth client;
8. access.

The `ask` binary gained `login`, `logout` and `-p`. Measured costs:
- encoding a 500-turn history: 1.02 ms (linear);
- assembly: 0.23 µs per delta at any length;
- linking AskAI into `ask`: idle memory +232 KiB, now 7,088 of 8,192.

## Where my memory was wrong, and probes caught it

- **RFC 7636's test vector.** I wrote the verifier from memory; the code disagreed, and openssl sided with
  the code. The RFC text, fetched, had a different verifier. The test was wrong, not the code.
- **The authorize URL and pasted-code rules.** Taken from pi-integrations by running it (bun) on 14 inputs,
  including one I had built wrongly: the reference trims before measuring length.
- **The transport "race".** I blamed the `async` response callback when a mid-stream failure lost the
  response. A trace showed the real causes:
  - URLSession withholds a response with no `Content-Type` until it can sniff one;
  - a stub that fails in the same call drops what URLSession had.
  The `async` form passes too, so the comment records a choice, not a fix.
- **CryptoKit's cost.** I assumed the new framework explained the +232 KiB. CommonCrypto measured
  identical, so it was reverted, per ADR-0016.

## Test bugs, three times

The quick first-run passes were not trusted, and three times the test, not the code, was wrong:
- a doubled comma made "refusal" tests pass on invalid JSON;
- chunks cut mid-event made a decoder test fail correctly;
- a fail-always stub met the correct rewrite path.

Mutations are what separate these cases.

## Equivalent mutants removed

The SSE comment check and the OAuth empty-state guard could not change any outcome. Both were removed
rather than kept as untestable code.

## Decisions

- Credentials go in an owner-only file, refused when exposed (ADR-0018). The Keychain is deferred until
  ask ships signed builds.
- ask identifies itself as `ask`, not as another client. The gate bisection says headers do not matter;
  the first live call is the probe.

## Waiting on the user

`ask login` needs a browser sign-in once. Then `ask -p` is the first live run, and the three claims above
get their probes.
