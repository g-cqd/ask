## Measurements (ADR-0016)

`Scripts/measure-budgets.py` on shipping release binaries, isolated config/state, no real credentials.
The before build disables the new command's registration/routing; the after build enables it.
Other transition code is linked in both, so this isolates making the feature reachable rather than
claiming a complete parent-commit binary comparison.

Two independent 12-run batches were noisy (cold medians 14.90 and 19.99 ms), so they were not used to infer
a cost. Then 16 pairs were interleaved, reversing A/B order on alternating pairs:

| Metric | Without /new, p50 [p25–p75] | With /new, p50 [p25–p75] |
|---|---:|---:|
| Cold, ms | 20.03 [13.76–22.16] | 21.36 [14.46–24.83] |
| Idle RSS, KiB | 9,256 [9,232–9,264] | 9,208 [9,184–9,228] |
| Input, ms | 0.474 [0.369–0.599] | 0.607 [0.310–0.683] |
| Signed-out Enter action, ms | 0.611 [0.401–0.962] | 0.453 [0.291–0.723] |

All medians remain inside the current approved budgets (24 MiB RSS, ADR-0038), with broad overlapping
spreads. No speedup or exact causal startup delta is claimed. The signed-out action is not model latency
or a re-derivation of 0007.

The first attempted interleaving accidentally copied the after binary following mutation tests rather than
after a shipping build. That comparison is discarded: tests can rebuild the executable with testability
and leave a mutant binary even after the source is restored. Both binaries in the table above were explicitly
built with `swift build -c release --product ask` before copying them.
