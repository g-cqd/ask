# Diary — 2026-10-26 (4)

## Accounts and models inside the conversation, the on-device model, and a sandbox that stops describing itself — ADR-0115, 0116, 0117

### Why

A person signed in to Codex alone could not use ask: the default was Anthropic, `ask -p "hi"` said `not signed in`, and the only way to Codex was to type `/model codex gpt-6-sol` blind. `/model` could not list, `/login`
and `/logout` ended the program, no Claude or OpenAI API key could be stored, and the effort was a launch flag. Separately, reading the code for what the model is told found the sandbox described to it six ways (ADR-0115).

### Built

- **Default provider** (`AutoProvider`): Claude, Codex, Antigravity, else Apple's model, chosen by name.
- **Lists** (`SlashCommand.takesChoices`, `ChoiceRow`, `ScreenController+Choices`): `/model `, `/thinking `, `/login `, `/logout ` open the picker with its keys and click; Enter or a click runs the command with the row.
  `ModelChoices` gathers every account's models in parallel with an eight-second patience; `ThinkingOptions` reads the efforts a model's entry names.
- **Questions** (`PendingInput`, `ScreenController+Input`, `InputBroker`): a command asks for a line; a secret is dots and a count, in a buffer that is not the draft.
- **Login once** (`AccountLogin`, `SignInInteraction`, `LoginRequest`): `ask login` and `/login` are the same code; API keys for Claude, Codex (OpenAI), every key preset and `custom NAME URL`; `ProviderFile` writes the endpoint
  without a key; `CredentialFile+Accounts` lists, stores and forgets (a Claude key replaces the subscription in one write).
- **On-device model** (`Sources/AskApple`): in-process `FoundationModels`; constrained tool arguments through a capturing tool; a measured window.
- **Sandbox**: the prompt, the per-request policy, the bash note, the file refusals, the widening refusal and `narrow_sandbox`'s answer no longer carry the policy.

### Evidence

All in the three ADRs. The shape of it: `probe-accounts.py` (23 checks, real binary, PTY), the live Apple probes, 19 new screen tests, five new AskAI suites (accounts, login words, API keys, providers.json, effort rules), 30 AskApple tests, and the sandbox tests rewritten from asserting the
leak to asserting its absence.

### Gate and the rest of the probes

`quality.sh` clean (format, lint, analyzers with five accept markers on tables and twin flows, the whole suite). On the shipping binary: `probe-accounts.py` 23 checks, three runs in a row; `probe-interactive.py` all sections I read
through K (it runs for minutes); `probe-picker`, `-picker-click`, `-files`, `-skill-picker`, `-input` exit 0 (they need `pyte`, which I installed in a venv); `probe-bash-environment` 12 ok. `probe-agent-run.py` asserted the old sandbox
wording in 12 places; I rewrote them to assert its absence. One check still fails, **and fails on the base binary too** (built in a worktree and run): the long-output file of probe F holds 12,833,344 bytes where it expects 10.9 MB.
It is in the job-output path I did not touch; not investigated.

`measure-budgets.py`, three interleaved pairs, machine loaded (the base's own cold start is 24.5–25.6 ms against 12 ms when quiet): idle RSS 10,016 → 11,968 KiB (+1.9 MB), cold start median +0.1 to +1.7 ms.

### Surprises

- **The framework was costing memory at launch, not in use.** My first `AutoProvider` asked the system whether Apple's model was available; idle RSS went from 10.0 MB to 19.3 MB on a machine with no account. Asking loads
  the model stack (6.3 MB). Launch now never asks; linking alone is +1.9 MB. A lazy link (`-lazy_framework`) was refused by the linker for the deployment target.
- **`ultra` again.** Codex's catalog advertises it and `ThinkingControlTests` already says live inference refuses it. I added it, the test failed, I removed it.
- **macOS 27 changed the error type** (`LanguageModelError`), so a guardrail refusal was unmapped until a live test hit it.
- The skills block said "a skill never changes the sandbox", which told a model there was one. The unit tests could not see it; `probe-agent-run.py` did, on a machine with skills installed.
- A probe of mine matched the previous question's text and typed a key into the editor. The probe waits for `Enter sends` now.

### Not done

The browser sign-ins from the screen are not exercised live (they are the old functions with `show` and `paste` rebound). The tool-call arguments of the on-device model are not streamed. Named connections stay account-only.
The Codex API key goes through chat completions; Responses is open.
