# 2026-11-14 (07): what a command waits for, and two things it no longer does

The owner's choice after entry 06: investigate the command's cost before touching CI, numbers first. The note is
`development/research/command-cost-2026-11-14.md`; this is the probe log and what changed.

| Claim | Probe | Verdict |
|---|---|---|
| A person's sandboxed command takes the 97 ms the probe showed | the same leg with `HOME` the account's | **Fails**: 66.5 ms. The probe's empty `HOME` gives ask two homes to protect, 198 path rules instead of 102 |
| The profile's rules are what `sandbox-exec` spends its time on (entry 06 said "0.2 ms a path") | the same 198 paths as `(param …)` and as text; n parameters each used once; uses of the first and of the last | **Fails**: 52.1 ms as parameters, 16.1 ms as text. 50/100/200/400 parameters cost 3/12/48/194 ms over an empty profile: a linear search for each |
| shellcheck's 21 ms is work on the command | `shellcheck --version` | **Fails**: 21.4 ms. It is the program starting |
| Homebrew's bash starts as fast as the system's | `bash -c :`, 15 runs each | **Fails**: 9.6 against 2.3 ms |
| Writing plain paths as text keeps every protection | the prototype, all sandbox suites under the real `sandbox-exec`; a spliced hostile path; a profile mixing both forms | **Holds**: suites green but for three tests of the profile's text; the hostile path does add a rule when spliced, and stays a parameter under the allow-list |
| shellcheck can start while the shell parses | a fake shell that ends its parse only once a fake shellcheck has started | **Holds** after the change; red before (the shell gave up, exit 9) |
| A command that does not parse does not wait for shellcheck | a shellcheck that sleeps 30 s, a 4 s deadline | **Holds**: answered in under 2 s |
| A clean command need not be checked twice | a shell and a shellcheck that log each start; `echo ok` three times | **Holds** after the change: one parse, one shellcheck, three runs; red before (three of each) |
| What the check says is read again every time | a finding that does not refuse (SC2034) on a failing command, twice; a command that does not parse, twice | **Holds**: two shellcheck runs; four parses in all |

Put to the owner with the numbers: plain paths as text (A), the two checks side by side (D), no second check of a clean command
(G). Chosen: **D and G**. A is not built; ADR-0020 stands as it is.

## What changed

- `CommandCheck.check` starts shellcheck in a task before it awaits the parse, and returns a parse failure without awaiting it.
- `CleanCommands` (beside `RefusedCommands`): the commands a check found clean, for their shell and `PATH`; at most 256, none over
  4 KiB, forgotten when the `PATH` changes. `BashTool.check` asks it first. The person's own `!` commands were never checked.
- `Budget`'s comment and `measure-action.py`'s said a sandboxed command adds "its spawn, about 16 ms": both now say what it is.

## Measured, before and after, interleaved (a person's home, Homebrew bash, shellcheck)

| | Before | After |
|---|---|---|
| A new command, to its result on screen (12 runs, twice) | 65.4, 64.3 ms | 55.8, 54.9 ms |
| 60 different commands in a row, each (with the model's round trip) | 65.7, 63.1 ms | 56.1, 58.5 ms |
| 60 times the same command, each | 66.2, 66.2 ms | 33.6, 32.5 ms |

Not verified: on a Mac whose bash is the system's the first row's gain is smaller (the parse is 2 ms there, so shellcheck's 21 ms
still bound the check). Mutation results are CI's.
