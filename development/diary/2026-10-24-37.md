# Diary — 2026-10-24 (37)

## Addressing the formal-models report: the session file's failure paths (ADR-0084)

The last three items of the report, the ones it listed as "read and not probed". The method was the report's own: nothing was changed
until a test had failed one system call and shown what happened.

## What the probes showed

| Claim | Result |
|---|---|
| `begin` leaks the descriptor when the lock cannot be taken | **Confirmed**, after a false start: my first probe passed, because the helper that asks the kernel which files the process holds open could not see anything (Foundation shortens `/private/var` to `/var`, the kernel reports the long form). A positive control for the helper (open a file, see it; close it, don't) exposed that, and then the leak was red |
| `.damaged` backups pile up when the rename fails | **Confirmed**: four copies of the same bytes after three failed renames and one success. Each failed attempt re-linked the original as the next free name; after a thousand the session could no longer persist |
| A record stays on disk after a failed flush | **Confirmed**, and **not changed**: an existing test pins that a torn fragment stays and is kept as `.damaged`, because ADR-0013 says damaged bytes are never discarded. The flush case is the same principle (the bytes may already be durable), so the behaviour is pinned by a new test and documented, not "fixed" by truncating |

## What was built

`SessionFileCalls`: one value holding the record write, the flush, the rename and the lock adoption, real by default, so a test can fail
exactly one. `begin` closes its descriptor on the failure path. `preserveOriginal` stops when a backup is already the same file.

## Mistakes

- The probe that passed for the wrong reason (above). A probe that cannot fail is not a probe, and I only found out because the leak
  was predictable from the code and the test said otherwise.
- My first design for the flush case was to truncate the record away. Reading the existing torn-append test before writing it stopped
  that: it would have contradicted a recorded decision, not just changed a behaviour.
- The `SessionFileCalls` seam first needed `Sendable` closures, then did not: the file is `~Copyable` and not shared, and an
  `@unchecked Sendable` would have needed a justification the code does not have.
