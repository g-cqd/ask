# 2026-11-15 (18): codemode, built: a script over the tools, in JavaScript

Roadmap 0012, ADR-0156, steps 1 to 6 of its order of work. The model can now write one JavaScript script that calls ask's tools,
and it is on by default. Python (step 7) is not built.

## The parts, in the order they were made

| Part | Where | What it is |
|---|---|---|
| The VM | `AskCodemode/CodemodeVM`, `CodemodePrelude` | One script in one JavaScriptCore context, on a thread of its own. The surface (`tools`, `ALL_TOOLS`, `text`, `console`, `exit`) is added and frozen; nothing has to be taken away |
| The host | `AskCodemode/CodemodeHost`, `ask codemode` | A child of ask, asked to run one script; asks back for each tool; watches its own footprint |
| The wire | `AskCodemode/CodemodeWire` | `run` and `call`, JSON-RPC lines, both ends through one file |
| The loop | `AgentLoop+Nested`, `NestedTools`, `ToolContext.withinScript` | A tool is handed the means to call the others, through the hooks and the sandbox |
| The keeper | `AskTools/CodemodeKeeper`, `CodemodeCalls`, `CodemodeLimiter`, `CodemodeChild` | Starts the child over the MCP client's stdio transport, serves its calls, holds it to its limits |
| The tool | `AskTools/CodemodeTool`, `CodemodeLimits`, `CodemodeReport` | `codemode({code})`; the options line; the result in pi's shape |
| The wiring | `ApprovalPolicy`, `ToolSummary+Script`, `Configuration.codemode`, `codemodeTools` | Asked about once; shown as "script of N lines calling …"; `"codemode": false` |

## Probes

| Claim | Probe | Verdict |
|---|---|---|
| JavaScriptCore's callbacks can live in an actor | the VM written as one | **Fails** to compile: the blocks are synchronous and carry values that are not sendable. A VM on a thread of its own, with the answers to its calls brought to it, is what JavaScriptCore is made for anyway |
| A script costs about 30 ms of process (what the owner was told when choosing) | `ask codemode` driven over pipes, 15 runs: one script with one call, start to exit | **Better**: 11.5 ms median (min 10.9, p95 12.1). 200 calls at once: 13 ms |
| The child ends a script the VM cannot | `while (true) {}`; an allocation without end under `--memory 64` | **Holds**: the first is the keeper's to stop; the second ended itself in 23 ms, exit 86 |
| A tool's failure reaches a script in the tool's words | the host test | **Fails** at first: "The call of gone got no answer: the peer answered with JSON-RPC error -32000: …". The connection wraps a peer's error; the host now unwraps it |
| A nested call passes the hooks and is not asked about | `NestedToolCallsTests`, eight; six mutations | **Holds**; all six caught: self-call, the start as an event, a hook's context dropped, approval hooks skipped, the person asked again, the sandbox widened |
| No more than the limit of calls run at once | `CodemodeCallsTests`: 30 calls, a gate held by the test, `waiting(26)` | **Holds**: 4 in flight, 26 waiting; with the limit raised the test fails at its time limit |
| The whole, through the real binary | `Scripts/probe-codemode.py`, three runs of 4 s | **Holds**: (A) a script reads two files of 400 lines at once, runs a command, and returns "5 errors; built in …": the model's next request holds that line and none of the files; (B) a spinning script is stopped at its 0.7 s deadline, an allocating one at 256 MiB, no process left; (C) a write in the workspace lands, one to `/etc` is refused and the script is told; (D) through `ask serve` the person is asked once, with the script shown and "script of 4 lines calling write" in the question; allowed, its write is not asked about; denied, nothing runs |
| The probe can fail | the installed ask, which has no codemode | **Holds**: 5 checks fail |
| Linking JavaScriptCore and offering the tool is within the budgets | `measure-budgets.py`, 12 runs, before and after interleaved, twice | cold start 38.7 / 37.7 ms before, 38.6 / 39.2 after; idle 17.3 → 17.7 MB; active 27.9 → 28.7 MB, against 30 |

Found by the probe, and kept: ask's shellcheck refusal applies inside a script. The probe's own first command was refused for
an unquoted `$(…)`, and the script failed with ask's words.

## Tests that would not end

Twice more a mutation run hung instead of failing: a test helper waiting on a continuation (`CodemodeLimiter.waiting`) is not
ended by a time limit. It now ends when its task is cancelled, as `acquire` does. `SourceStandardsTests` then refused
`Task.yield()` in two of the new tests, rightly: they were hoping tasks would overlap. They now hold the overlap with a gate
and look at it.

## Known, and not what the ADR says

- **`max_output_tokens` above about 12,800 is not honoured**: every tool's output is capped again by the registry at 2,000 lines
  or 50 KiB. The ADR's table says "fewer or more".
- **A script stopped at its deadline or its memory loses what it had said**: its output is in the process that was ended.
- **`OutputCap` traps on a line limit near `Int.max`** (`(maximumLines + 1) / 2` overflows). Found by using it so; not
  touched, the report passes 2^40.
- Nested calls run at once through tools that had only ever been run one at a time. Reads and a command at once pass; the
  rest is not probed.

## Not built
