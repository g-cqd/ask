# 2026-11-10 (08): paths in ask's notices are shown short, and still copy in full (t214, roadmap 0215 step 4)

## Claim: a notice can show a shortened path without becoming Markdown

- `NoticePathsTests` on the build before: two of four fail. A notice drew `/work/project/Sources/a.swift:12:3` as written.
  The other two (`asWritten`, and a wrapped notice copying whole) passed before, as they should: they pin what must not change.
- `NoticePathRows` lays a notice out as plain text with the path hook's substitutions. `**Saved**` stays `**Saved**`: nothing is
  parsed. Each hard line is cut into pieces (text as written, or a path shown short over what was written), wrapped by `TextWrap`,
  and every row records its pieces as `RowSegment`s over the original graphemes, so a selection maps back to the notice's own text.
  A shortened path is one atomic segment: any part of it selected copies the whole path as written.
- Without a path display (no workspace), a notice is laid out as before, by the same code as before.
- Two mistakes of mine the run caught: the new file used `MarkdownPath.bytes` without importing its module (a compile error under
  MemberImportVisibility), and the copy test's drag ended one column before the final period. The second was the test, not the code:
  the copy held `Saved /work/project/Sources/a.swift now`, the full path, without the period I had not selected.
- `ReplyPathCopy` reads a notice as plain text too (no Markdown exclusions), since that is how it is drawn.
