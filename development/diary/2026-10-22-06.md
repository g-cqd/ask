# Diary — 2026-10-22 (6)

## Bounded input and display-row navigation, using TerminalKit

Roadmaps 0049 and 0051; ADR-0059. TerminalKit `99b3017` supplies `InputLayout` and `InputViewport` (its ADR-0032). Both manifests and both
resolved files agree with that pin; the actual checkout used by the tests reports `99b301799bc0f04e82314f8891b0c8038ec39f45`.

### What changed

- `PromptLayout` caches the kit's map until text or width changes and preserves the viewport top while the cursor remains visible.
  The old `ScreenComposer+Prompt` walk is gone. A benchmark-only copy records its cost; it is not linked into ask.
- `ui.promptRows` is a positive layered configuration key, default 6, capped to a third of the terminal. It limits display rows, not
  source text. Tiny terminals retain an input cell; a one-row terminal omits status, and a zero dimension produces no frame content.
- The existing status row shows the clipped range. On a narrow terminal, that cue precedes a long model label.
- The driver passes the actual width on every key and updates it on resize. Up/Down share the render map and preserve the wanted cell
  column across short rows. Home/End and Ctrl-A/E/U/K retain hard-line behaviour; the original editor API without width still works.
- Ctrl+X clears the whole draft without submitting it. Ctrl+U remains line-local. Enter submits the complete original edited source.

The new probe uses a local fake provider, disposable state/configuration, actual bracketed-paste and key bytes, and the actual session
records. It opens no visible window and touches no host clipboard. The folding probe's PTY harness now accepts dimensions and resize,
so the input probe does not introduce another emulator harness. An added tab fixture initially assumed fixed four-space expansion;
its failure exposed a wrong oracle: `InputLayout` documents **tab stops**. The corrected fixture starts its tab at column 7 (one space
to stop 8), then places the final caret at column 7 on the next row. It verifies the original tab survives submission and recording.

Three older layout fixtures expected six rows from a twelve-row screen or three from a six-row screen. Those contradict ADR-0046's
fraction cap. Their sizes now leave enough room for their original wrap/empty-line assertions; separate tests explicitly check the cap.

### Release input costs

`swift package benchmark --target RenderBenchmarks --filter 'input/.*' --no-progress --format text`, same release binary, 100 hard
lines (~6 KB). The old and new builders assert equivalent rows/caret on this sample before timing. CPU and wall time are both collected.

| Work | Wall p25 / p50 / p75 | Allocations |
|---|---|---|
| Legacy prompt row builder | 138 / 138 / 142 µs | 209 |
| New cold map builder, including source-caret index | 235 / 236 / 242 µs | 209 |
| Cached complete composer with the tall draft | 3.375 / 3.459 / 3.625 µs | 7 |
| Original hard-line Up API | 56 / 57 / 60 µs | 1 |
| Display-aware Up, rebuilding its map | 238 / 245 / 256 µs | 209 |

The richer cold map costs more than the old row builder. Renderer caching avoids paying that on cursor-only frames; visual navigation
still builds a fresh map per move. The builders and complete composer are different workloads, so this is not a whole-frame speedup
ratio. Further navigation caching is a measured opportunity, not part of this behaviour slice. These figures precede the small status
ordering fix; full correctness and PTY checks include it.
