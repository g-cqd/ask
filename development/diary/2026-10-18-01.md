## The probes, and what they overturned

Seven claims were tested. Two were refuted outright, and one more was refuted in its stated form.

**A flag was blamed for a build failure it had nothing to do with.** The test target could not resolve
`AskCore`. The strict upcoming features were the obvious suspects, so one was removed at a time and the
build was rebuilt. It still failed — which is the tell. The build failed identically with the entire
setting reduced to `.swiftLanguageMode(.v6)` alone. The flags were never involved.

Had the first result been taken as the answer, a constraint would have gone into the white paper
saying "these flags cannot be used with test targets". It would have been false, and it would have
outlived the investigation.

**Four "extra strict" flags turned out to be free.** `RegionBasedIsolation`,
`DisableOutwardActorInference`, `InferSendableFromCaptures` and `DeprecateApplicationMain` were added
as additional strictness. The compiler rejected all four: already enabled as of the Swift 6 language
mode. They are not in the settings, and the white paper says why — `.v6` is the only thing that
guarantees they stay on.

**`public` signatures failed on `URL`, and the cause was SE-0409.** `InternalImportsByDefault` makes
an ordinary `import Foundation` grant *internal* visibility, so `URL` was internal and every public
signature in the file was illegal. The first guess — that `URL` lives in `FoundationEssentials` and
that module needed importing — was wrong: the SDK does not resolve `FoundationEssentials` at all. The
fix is an access level on the import, `public import Foundation`.

**`@testable` was never about strictness.** Release builds fail to resolve `@testable`; debug builds
succeed. The cause is not the flags: SwiftPM passes `-enable-testing` only for debug builds. So
`ask` does not use `@testable` and tests run in the shipping configuration. Recorded as ADR-0002.

**Aemi publishes nothing.** `git tag` returns zero tags, so `from: "1.0.0"` cannot resolve and
`ask` has no version it could depend on. The dependency is deferred rather than pinned to a branch.
This is a real blocker on the Aemi-first plan and it needs a tag.

**The terminal stack was better than expected, and worse.** Synchronised output is already on the hot
path in `RenderPipeline.flush()`, which is the single most valuable thing a terminal UI can do, and it
is done. But there is no reset primitive at all — `restoreMode()` restores `termios` and nothing else
— capability detection reads environment variables and never asks the terminal, and the kitty keyboard
protocol is half-wired. The reset gap is the one with a user-visible failure: crash, and your shell is
left in the alternate screen with mouse reporting on.

## Decisions

- Package `ask` at `/Users/me/Developer/ask`.
- Terminal stack becomes `AemiTerminal` inside Aemi, with `AemiTerminalKit` as the umbrella product.
  ADR-0001.
- Release-only builds, no `@testable`. ADR-0002.
- Platform floor is macOS 26, not 27. ADR-0003: nothing in the package needs anything above 15, so the
  floor is decided on reach rather than on necessity, and it moves when a probe says so.
- `development/WHITE-PAPER.md` is the iteration preamble, led by the evidence rule.

## The documentation guards are not vacuous

Both new tests had only ever passed, which proves nothing. Each was probed by breaking it on purpose: a
300-line diary file made the line-budget test fail and name the file, and a roadmap file holding two
`## ` entries made the granularity test fail and name the file. Both were removed and the suite returned
to green. A test that cannot fail is not a test.

## Not yet done, and not to be assumed

- **No performance number has been measured.** Cold start, idle memory, input delay and
  action-to-action delay are named but unmeasured. Until roadmap 0004 lands, "ultra-performance" is
  an unmeasured claim and no decision may cite it.
- Whether DECSTR preserves scrollback on every terminal `ask` will meet is still an open question.
- Whether `-warn-long-function-bodies=100` is too aggressive for real source files.

## The aemi note

The two Aemi clones were separate clones of one remote at different commits, with 42 "unpushed"
commits in `ongoing/swift/Aemi`. Those 42 were not lost work: 26 had upstream equivalents, and the
remaining unique commit had been **squash-merged** upstream under a new SHA, so the content was
already on `main`. Proven, not assumed — a file-level diff showed **zero** files present locally but
absent upstream before anything was reset. Both clones are now byte-identical at `47efa90`. The old
mirror is preserved at `backup/pre-sync-aemi-swift-20261017`.
