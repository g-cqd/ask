# Diary — 2026-10-20 (53)

## `ui.*` in the configuration file

The screen's pointer and fold defaults (ADR-0046) were constants in `ScreenOptions`. They are now keys a file can set, layered like the
rest of the configuration (ADR-0030), shown by `ask config` with where each came from, and read at startup.

```json
{ "ui": { "mouse": true, "copyOnSelect": true, "tools": "folded", "scrollLines": 3 } }
```

- `ui.mouse`, `ui.copyOnSelect`, `ui.tools` (`"folded"` or `"open"`) and `ui.scrollLines` (at least 1). A key a layer does not set keeps what
  the layer below set; with nothing set the screen's own default applies, so a default lives in one place (`ScreenOptions`).
- **Keys nothing reads are refused**, not accepted: `ui.thinking`, `ui.images`, `ui.codeFoldLines` and `ui.promptRows` are in ADR-0046
  but have no feature behind them yet, and a file must not promise what is not there. Each is added with its feature.
- A project's file may set `ui` (it cannot widen anything).

### What was checked

| # | Claim | Evidence | Verdict |
|---|---|---|---|
| 1 | Every key parses, in JSON5; unknown keys, a bad `tools` and `scrollLines: 0` are refused naming the key | 8 tests | **CONFIRMED** |
| 2 | Layers replace per key and leave the rest | three layers, the third setting one key | **CONFIRMED**; a layer that wipes the others fails |
| 3 | A reload names a `ui` change | `changes(from:)` | **CONFIRMED** |
| 4 | The real binary reads the file | `ask config` with a temp `XDG_CONFIG_HOME`: `ui  mouse off, tools open, scrollLines 5  [path]`; a bad value gives `"ui.tools" is "hidden": use "folded" or "open"` | **CONFIRMED** |
| 5 | The tests can fail | four mutations | **ALL CAUGHT**, after strengthening one test and redoing another |

### What went wrong

- **The layering test passed under a mutation** because both layers set the same key, so wiping it changed nothing. A third layer that
  sets only another key exposed it.
- **A failing test crashed the whole run** (it indexed `lines[0]` after a failed count check), which hides every other result. It now
  fails cleanly.

### Not verified

- **The mapping from the setting to `ScreenOptions`** is in the executable, which has no test target. The binary was run for the report,
  not for the screen: nobody opened the TUI with `mouse: false` and looked at what the terminal does.
- **No environment variable or flag** sets these (`ASK_UI_*`, `--no-mouse`); only files do.
- **A change is read at startup**; `/reload` re-executes ask, which re-reads it, but a live change of a `ui` key was not tried.
