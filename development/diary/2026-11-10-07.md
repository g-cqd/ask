# 2026-11-10 (07): copy complete relative reply references as absolute paths (t214, roadmap 0215)

## Claim and regression

The original copy reads selected source verbatim. `ReplyPathCopyTests` on that implementation fails four expectations:
complete relative references in replies/notices do not expand, including reverse selections and references on two hard lines.

The new copy helper leaves the transcript, display and selection coordinates untouched. It first computes the selected source
byte range, expands only whole accepted relative path tokens in that range, and preserves location suffixes and punctuation.
It calls the same policy-aware acceptance hook as rendering. Partial references, unavailable/denied paths, user messages, queued
messages and tool output keep literal text. Both drag-to-copy and Ctrl+C route through this helper.

## Corrections made from failing checks

- Scanner input is a prose run, not an entire multiline message. The first version missed the path after a hard newline;
  copy now scans each hard line and retains global source offsets.
- AemiMarkdown container events have empty ranges. Logging the real parser events for a code span showed `codeSpan` entering
  at 0..<0 with a text leaf at 1..<16. Exclusions now collect leaves under code/link/math containers rather than container
  ranges. The trace was removed. No filesystem lookup is made for excluded code or link content.
- The test fixture initially left Markdown off; it now explicitly enables it when checking Markdown exclusions.
- A drag endpoint initially stopped before the final period. The endpoint was corrected; source punctuation is not invented.

## Scope

Inline code, fences, math and explicit Markdown link/image content remain literal in Markdown mode, matching the existing
prose path hook. Absolute paths are already full; `~/` references expand against the configured home. No stat is needed to
expand a home prefix. The helper does not infer a complete path from a selected fragment. Existing coordinates remain useful
for highlights and word selection because transformation happens only on copying.

## Validation

`Scripts/quality.sh --check` passed, including the mixed-block selection and summary/no-authority cases. The focused copy suite
covers reverse/multiline/partial selections, literal code and links, and both actual mouse/keyboard copy routes. No local
mutation or real-terminal checks.

`ReplyPathCopyCostTests` is the reproducible optimized measurement: nine interleaved samples of 100 copies, a ~300-character
reply and one accepted relative path. Source-only copy and resolved copy intentionally produce different output. The focused
run measured source median 5.516 us (5.501–8.871), resolved median 43.128 us (42.486–44.660). Lookup is an injected accepted-path
closure here; filesystem/cache cost is measured separately in diary 06. This is copy-action feature cost, not per-frame latency.
No timing threshold is asserted; every iteration checks the correct output.
