## What was built

A left click on a match row inserts it exactly as Enter does (trailing space, a file's `:range` kept, nothing sent). The composer now
records, with the frame's other geometry, the row of the first match, which matches were drawn and the word the list was for
(`FrameGeometry+Picker`); the pointer gets a region over those rows only while the list has some. `CompletionPicker.choose` selects the
clicked match and `accept` is the same function Enter uses, so there is one way to insert. The window arithmetic moved out of
`pickerLines` into `ScreenComposer.window(of:rows:)` so the row a click maps to and the row that was drawn cannot come from two
formulas.

## What the probes showed

- **Confirmed, in the first red run:** ten of eleven new tests failed before the code and the "chooses nothing" ones passed trivially,
  as they should; the tests were run red this time.
- **My test, not the code, was wrong, twice.** The first stale-frame test used the rig's `click`, which redraws between press and
  release as the real driver does (it loads the newest frame for every mouse event), so it was testing a fresh frame. A click means the
  frame at the moment the button comes up; the test now sends press and release straight to the controller to hold the old frame, and
  a second test says what the redraw case means.
- **An escape that was real:** replacing the window's start with the plain first-visible index was not caught. The cause was that no
  test made the list shorter than its capacity, which is the only layout where the two formulas differ. The new test builds it (twelve
  rows, a runners list open, a two-line prompt: two list rows of three) and the mutant is caught.
- **Two escapes that were dead code:** `choose` repeated a bounds check its one caller already makes, and called `settle()` for a row
  that was already in view. Both removed rather than tested; `choose` is one line now.
- **Two lines I had added for parity were not needed:** Enter's path neither clears the selection nor refreshes the picker (the cursor
  ends after the inserted space, so there is no word to refresh). Removed from the click path.
- **Real binary** (`Scripts/probe-picker-click.py`, PTY, fake provider): 7 checks. The control, the baseline binary, leaves the draft as
  it was after the same click. A click on the title, the status line and the transcript chooses nothing; a click on a command row,
  far along the row, inserts it without sending; the second row inserts the second match, not the chosen one; a file row inserts
  `@beta.txt `.
