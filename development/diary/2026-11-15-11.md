# 2026-11-15 (11): a saved session is loaded and replayed

Roadmap 0234 step 2, `session/load`. Read first (Session Setup, "Loading sessions"): the client names the id, the directory and
the MCP servers; the agent replays the whole conversation as `session/update` (a person's message is `user_message_chunk`),
then answers `{}`; live notices are not history and are not replayed; `loadSession` in the capabilities says it can.

| Claim | Probe | Verdict |
|---|---|---|
| The conversation already knows how to say a saved session | `AgentConversation.history()`, what the screen shows on `--resume` | **Holds**: prompts, text, thinking, tool calls with how they ended. The replay is that list through the reader a live turn uses |
| A saved session is opened by its id, for its folder only | `ServedSessionsTests`: a session file of one folder, loaded there, from the other folder, under a missing name | **Holds**: opened and continued by the conversation; none elsewhere |
| An id cannot name a file outside the folder's sessions | ids `../outside` (a real file beside the directory), a path, a name with its extension, a space, empty | **Holds**: none is a session; red when the name check is removed (the file outside was opened) |
| It has one writer | the same id loaded twice | **Holds**: the second is refused, "open in another ask", by the file's lock; on one connection the protocol's library refuses before asking |
| The whole works over pipes | `probe-serve.py`, part D: a second `ask serve` loads the first's session | **Holds**, three runs: both prompts replayed as the person's, the answers as the model's, the three calls with completed, completed, failed (the denied write), nothing asked again; then a prompt continues it with its history, in the same file |
| The tests can fail | six mutations at once (notices replayed, a second load allowed, lists not flattened, a prompt replayed as the model's, the name check, the session not resumed) | **Holds**: four tests red |
| The probe can fail | the installed ask, which cannot load | **Holds**: part D fails |

Built: `ACPSession.Loader` and `Loaded`, `ACPSessions.load`, `ACPTurnReader.replay`, `loadSession` in the capabilities when a
loader is given; `ServedSessions.load`, which opens the file as `--resume` does but throws where the launch exits.

Decided here: a session's id is its file's name and nothing else, so only letters, digits, `-` and `_` name one. An encrypted
session whose keys are not open is refused with what to do (`ask --resume ID` in a terminal, once): a password is never asked
through a client (ADR-0154).

Not built: a compaction's replay (`compaction_update`), pictures of a prompt, `session/resume` and `session/close`
(capabilities ask does not advertise), `mcpServers` of the load. A call that was running when its session stopped is replayed as
begun and never ended.
