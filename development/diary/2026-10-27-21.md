### Implementation

- Bash definitions are built from the shell resolved through the run's filtered
  `CommandEnvironment`. The description names the executable and shell syntax and
  states that `shell` overrides it. Explicit shell arguments remain validated as
  absolute executable files. Restricted POSIX job scripts retain bash internally;
  this hint concerns model-authored commands.
- `ShellReadiness.select` rejects ambiguous modes, empty strings, invalid ports,
  network-disabled ports and unauthorized file paths before a job starts.
- `ShellReadiness.wait` races readiness, job completion and timeout without
  consuming output. File events recheck the opened object's real location through
  `ScopedFile.exists`; cancellation of a non-cancelled file watch reports failure
  instead of claiming readiness.
- Bash uses readiness for output/port/file. A readiness result marks the launch as
  background; a process that ends is reported through the normal finished result.
  Readiness uses `timeout_seconds`, while plain yield still uses `yield_seconds`.
- `job` gains action `wait`, plus `wait_for_output`, `wait_for_port` and
  `wait_for_file`. It resolves IDs/aliases but never marks a pre-existing job as
  backgrounded and timeout/cancellation leaves it running. Input can send text and
  then wait transitively. Stop/status reject readiness parameters; wait rejects
  input/EOF parameters.
- Shared input/EOF and readiness waits were factored into `Job+Input` and
  `JobWaiting+Readiness`; duplicated declarations were reduced until Dolly was clean.
  Two cross-file false-positive near-clones were accepted with explicit reasons.
