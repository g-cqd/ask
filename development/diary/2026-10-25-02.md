# Diary — 2026-10-25 (02)

## Telling the person when a sign-in could not be saved (ADR-0091, roadmap 0056 follow-up)

"Sure, go ahead": the first of the two items I proposed from the re-assessment, the one gap I had left open in ADR-0082. Worktree
`ask-notice` from `origin/main`.

## What I found before building

- The channel already existed end to end (`ModelEvent.notice` → transcript notice, and stderr in `-p`) and nothing used it. So the work
  was smaller than I had assumed.
- It had never been exercised, and it had a bug: the assembler threw `notStarted` for any event before `messageStarted`. A provider that
  sent a notice first, which is what a credentials notice naturally is, would have ended the run. The first red test is that.
- `Sources/ask` has no tests (roadmap 0028), so the logic went into libraries where it can be tested, leaving only wiring in the
  composition root: `RotationNotice` (when to speak) in `AskAI`, `NoticingProvider` (where to say it) in `AskAgentCore`.

## Evidence

| What | Result |
|---|---|
| Tests | 6 for `RotationNotice`'s states and wording, 6 for `NoticingProvider` including a real `AgentLoop` run that carries a notice, the assembler accepting notices anywhere, and `unsavedReason` on both accessors; 26 neighbouring tests unchanged and passing |
| Compiling mutants | 14, all caught by a named assertion (two needed rewriting because they did not compile) |
| Strict gate | passes |

## Not covered, and why

- **The real binary.** The token endpoint is a constant by design, so no run can rotate a token and then fail to save it; the probes for
  this path are unit tests that drive the real accessors and the real loop.
- **The wiring.** Two wrappers in `Composition.swift` are untested glue (roadmap 0028 item 2). A mistake there would show as no notice,
  not as a wrong one.
- **I said earlier that this would also fix roadmap 0053's "a lookup's own notices are not displayed". It does not**: that is a different
  path (the model-list lookup, not a provider stream). Corrected here.
