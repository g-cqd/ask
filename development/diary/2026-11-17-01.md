# 2026-11-17 (01): what a model is told about the tools

The owner, after the session's three items: the information passed to models about the tools could be improved, and with no
user base relying on a tool's shape, tools doing the same thing could be one. Agreed in three steps: count where models go
wrong; say more, where it is read, without changing what a tool does; then consolidate, a decision at a time, the owner's.
This diary is steps 1 and 2. ADR-0157 holds the rule; `research/tool-calls-in-sessions-2026-11.md` the counts.

## Step 1: where models go wrong

| Claim | Probe | Verdict |
|---|---|---|
| Models mostly fail on arguments | `Scripts/measure-tool-errors.py`: 197 sessions, 47,074 calls, 1,780 failed | **Refuted**: 68 of 1,780 are refused arguments. 552 are commands refused before running, 131 a name not found, 1,029 the world saying no |
| `tasks` is refused for limits it does not state | The 42 refusals read | **Holds**: 28 a title over 120 characters, the others a field or value its operation does not take |
| shellcheck's refusals are few kinds | The 269 read | **Holds**: SC2010, SC2164 and SC2046 are 234; and the rate rose from 0.3% to 1.7% of commands in a fortnight |
| A file not found is a path from the wrong place | The 114 "No file at" by the path given | **Holds** for 90, relative; 23 absolute |
| The system prompt names the tools there are | Read against the tools offered | **Refuted**: "wait, job_input and job_stop", folded into `job` |

The same was seen from inside while doing this: the session's own agent was refused twice for `ls | grep` in the hour.

## Step 2: said where it is read

Changed, with no tool doing anything it did not do:

- `ToolProperty.described(_:)` and a `ToolSchema.Field`'s description: an argument says what it is, in the schema.
- Every tool's description is a first line of what it is for, then what cannot be guessed. Every argument of the sixteen
  tools ask declares says what it is: the default, the unit, the limit it is refused for.
- `bash` says a command is checked, names the three findings that are nine in ten, and says a `cd` lasts one command.
- `tasks` says which operation takes what, and the title's limit. `tasks` and `notes` are built by one `ListToolSchema`.
- The system prompt says `job`.
- `ToolDescriptionsTests` is the gate; each of its three checks was made to fail once (ADR-0157's table).

| Claim | Probe | Verdict |
|---|---|---|
| The tool list did not grow much | `Scripts/measure-request-size.py`, main's binary and this one | **Refuted**: 8,169 to 12,035 bytes, +47%. A first cut was 12,736; trimming repeats took 700 |
| `sandbox` needs a phrase on each of its three fields | The gate, on the first cut | **Refuted by choice**: +304 bytes over four tools to say "Writable paths; no others." The gate takes an object that names its fields in its own phrase, and `sandbox` keeps its bytes |
| The real binary still runs its tools and scripts | `probe-agent-run`, `probe-codemode`, `probe-codemode-at-once` on the new binary | **Holds**: PASS, each once |

Defaults taken: `write`'s `new_text`-alone alias stays and is no longer advertised; the three tools no model is offered
(`edit`, `wait`, `job_stop`) are left as they are, outside the gate by name.

Open: whether any of the counted failures drop. Only sessions after this binary is installed can say; the script is the probe.

### Waiting in one place (ADR-0159)

`bash` keeps the three `wait_for`; `job` waits for the end only, and says where a `wait_for` goes when given one.

| Claim | Probe | Verdict |
|---|---|---|
| My candidate: waiting belongs to `job`, `bash` keeps `yield_seconds` | The counts: 34 `wait_for` on `bash`, 2 on `job` in 561 calls; and one call against two | **Refuted**: it lives where the command starts |
| Ignoring a `wait_for` given to `job` is harmless | Read: the wait sits out its time for what it never watched, and says nothing | **Refuted**: refused, with what to do |
| `probe-wait-gap` still probes something | Read `Job.wait(for:)`: the joined ends are searched only by a wait that starts after output | **Refuted**: no tool starts one now; removed, the buffer's unit tests stay |
| The probes that waited on `job` for a port still pass with one `bash` call | `probe-agent-run`, `-codemode`, `-codemode-at-once`, `-job-lifecycle`, `-jobs-keep-finished`, `-runners`, `-sidebar`, `-interactive` on the new binary | **Holds**, after one check of mine named a headline the binary does not print |
