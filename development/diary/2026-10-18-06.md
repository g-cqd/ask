# Diary — 2026-10-18 (06)

## The green build was green against a commit TerminalKit had moved past

`Package.swift` declared TerminalKit as `branch: "main"`, and `Package.resolved` pinned
`8e8fc85`. TerminalKit `a4bce90` had renamed the codec enum from `KittySequences` to
`EscapeSequences`. Every build in this repository was passing against an API that no
longer existed upstream.

**Probe.** A copy of the repository in `/tmp`, so the live tree stayed clean:
`swift package update terminalkit`, then `swift build -c release`. The pin moved to
`7a1f22a` and the build failed at eight `cannot find 'KittySequences' in scope` errors
in `AskTUI.swift`.

**Confirmed** — and it refuted something I had been reading past. `branch: "main"` reads
like tracking upstream; what it actually means is that the *lockfile* decides, and the
lockfile had not been touched since the rename.

Diffing `8e8fc85..7a1f22a` with rename detection showed exactly two renames:
`KittySequences → EscapeSequences` and `KittyLogger → TerminalLogger`. `ask` uses the
first and not the second, so the rename surface was one file and eight call sites. Fixed
in `d5099ea`; the branch declaration now means what it appears to mean.

The same commit cleared two warnings the build had been carrying without anyone reading
them: a deprecated `package(name:url:branch:)`, and an executable target importing
`AskCore` without declaring it. Both are now gone, and `swift build -c release` reports
zero warnings.

## An AGENTS.md would have been inert, and reading the docs would not have said so

The intent was to give this repository an `AGENTS.md` plus skills for its two real
workflows. Before writing it, the question worth asking was whether one file would
actually reach the harnesses it is meant to serve.

Claude Code reads `AGENTS.md` natively. **But** `~/.claude/settings.json` sets
`CLAUDE_CODE_DISABLE_CLAUDE_MDS=1`, and that covers project memory files, not just
user-level ones.

**Probe.** A scratch repository with an `AGENTS.md` containing a magic word, asked to
report it or `NONE`:

| Condition | Result |
|---|---|
| as configured | `NONE` |
| `env -u CLAUDE_CODE_DISABLE_CLAUDE_MDS` | the magic word |

**Confirmed, and the documentation alone would not have caught it** — the env-var page
says "user, project, and auto memory files", which is accurate but easy to skim past
when the whole point is a *project* `AGENTS.md`. Removed the key; re-probed in place and
`AGENTS.md` now loads.

A second probe, on skill discovery, was worth running for the same reason. Pi documents
`.agents/skills/` as an Agent Skills location. Claude Code's skill docs list
`.claude/skills/` and never mention `.agents/` — and a probe agreed: a skill placed only
in `.agents/skills/` was **not** registered as a slash command in Claude Code.

So the skills live in `.agents/skills/` as the single source of truth, and
`.claude/skills` is a **symlink** to it. Git stores mode `120000`, so the link travels
rather than becoming a second copy that could drift. Both harnesses were probed
afterwards and each reported both skill names.

## What was written, and what was deliberately left out

`AGENTS.md` at 124 lines, under the same 200-line budget the white paper is held to by a
test. It does not restate the principles — that is what `development/WHITE-PAPER.md` is for, and
duplicating them would create a second copy to keep in sync. A probe confirms Claude Code
reads it and correctly identifies `development/WHITE-PAPER.md` as the definition of the evidence
rule.

Two skills, because these are the workflows this repository has and the general roster
does not: `probe-before-adopting` and `documentation-law`. Each carries its refuted
beliefs as worked examples, on the reasoning that a confident wrong belief corrected in
writing teaches more than a rule that was never questioned.

No subagent definitions. The general roster in `skills/agents/` already renders to six
harnesses from one neutral source, and duplicating that roster here would put two places
to update a tier mapping. If `ask` later needs its own workers — a budget verifier, say —
that belongs as a `agents/src/` addition to the roster, not as a second roster.

## Verification

`Scripts/quality.sh --check` clean on both commits; 17 tests, no formatting or lint drift.
All four budgets re-measured and inside their limits: cold start 6.23 ms / 25, idle
5728 KiB / 8192, input delay 0.10 ms / 2, action-to-action 0.04 ms / 2, harness exit 0.

Cold start reads better than the recorded 11.06 ms baseline. That is variance at this
scale — a rename of a symbol cannot change process startup — and it is recorded here as
an observation, not as a result from the rename.

## Still owed

- **`branch: "main"` is still a floating declaration.** `d5099ea` made the lockfile
  current; it did not make it stop drifting. A revision pin is the mechanism the rest of
  the ecosystem uses — TerminalKit pins Aemi that way, and `ECOSYSTEM.md` records
  "One Aemi, one pin" as a cross-repository decision. Converting `ask` to a revision pin
  is a small manifest change and wants its own commit and probably its own ADR, since
  it trades "tracks upstream automatically" for "cannot break under you". **Not done,
  because it is a decision, not a rename.**
- **The action-to-action budget is still provisional.** Unchanged by any of this. It
  measures Enter producing the next prompt in a program with no agent in it, and must be
  re-derived when the agent loop lands.
- **`~/.claude/settings.json` is now changed outside any repository.** The backup is at
  `~/.claude/settings.json.bak-before-agents-md`. That file is not under version control,
  so nothing here would catch its being reverted.
