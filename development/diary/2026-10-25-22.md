# Diary — 2026-10-25 (22)

## What happened

The user supplied a subscription HTTP 429 with weekly status `rejected`, weekly utilization `1.0`, five-hour status `allowed`, and organization-disabled overage. Pi called it possible protocol drift. These headers instead explicitly report weekly quota exhaustion, resetting at 2026-10-28 04:00 UTC.

Pi's diagnostics now prioritize explicit quota rejection, show reset timestamps and overage restrictions, and omit drift instructions for those failures. Ambiguous 429s retain their existing diagnostics. Its SDK retry policy is unchanged.

ask's decoder now receives the HTTP status and headers through a protocol requirement with a body-only default. The Messages decoder maps explicit rejected quotas to the existing non-retryable `usageLimit`, even with an unreadable body. Other decoders keep their existing behavior. Reset timestamps are bounded and validated before formatting; the error path does not echo arbitrary header values.
