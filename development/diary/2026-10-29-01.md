# 2026-10-29 (01): row windows from the end, and a Page Up that did not scroll

The transcript is laid out from its end on demand (0088 step 2, TerminalKit 0023 done at e2607ad). On a copy of the owner's 12 MB session:
open 440 to 230 ms, a new width 231 to 15 ms, resident size 60.9 to 52.7 MiB; a fresh screen unchanged. Page Up costs 2.5 ms instead of 1.3,
the layout of the page it reaches.

Checking that the top of the session was still reachable found that Page Up did not scroll at all until a mouse event: the screen loaded
the frame's geometry for mouse events only. It was so in every build, and the first half's Page Up figure had timed frames that did not
move. Every input loads the frame now. Paged to the top, the from-end build draws the same screen as the full layout, with the same 16,148
rows below. The probes' scrolling pyte (`probe_screen.py`) is needed for such a check: plain pyte ignores SU and SD and shows stale rows.

The first profile of the from-end Page Up showed the frame walking every item below the window, and a generic dictionary unspecialised
across the module boundary; then a folded header counting its output's lines by splitting it. Both are fixed, with tests
(`WindowedLayoutTests`' random steps against the whole document, `HardLineCountTests`).

soft breaks are line breaks now. probe-code runs twice, text and Markdown; the open block keeps its header there, and its code sits two
columns further in, so the probe finds the drag's end from the row. 48 probes pass.
