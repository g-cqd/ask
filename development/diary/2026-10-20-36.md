## Evidence

The new real-PTY P probe failed before command registration: the screen said there was no /resume command.
With the implementation, P and the extended job-guard probe O check:

- No sessions: say so, create none, and make no provider request.
- Two sessions: list both names without selecting one or sending a model request.
- Ambiguous prefix, unknown name, missing file and locked archive: refuse; the next prompt still sends session B's
  context, not A's.
- Switch to A: draw only A's history and usage; Python can lock B and cannot lock A while ask stays open.
- Opening is read-only: A's bytes do not change just because it was selected.
- Select A again: no lock error and no double-counted usage.
- Continue A: the provider's actual request carries A's exchange, not B's, and B's file stays unchanged.
- Resume a torn archive: report the repair, leave damaged bytes untouched on read, and preserve them byte-for-byte
  as `.damaged` on the first later prompt.
- With a running background job: refuse resume, retain the old writer lock, and keep the job and context alive.

Four compiling mutations were killed by actual-binary probes, with their failures inspected:
1. Drop the active session before opening the replacement: B's context disappears after an open failure.
2. Swap the recorder without resetting/replaying: old history and usage remain.
3. Omit the interactive repair notice: the notice assertion fails while repair/preservation still work.
4. Omit resume's running-job guard: the refusal is absent and the original writer lock is released.
