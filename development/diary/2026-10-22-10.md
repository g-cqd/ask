# Diary — 2026-10-22 (10)

## Edge autoscroll for a held drag — roadmap 0051, ADR-0061

TerminalKit stays at `99b3017`; this is host policy and time (ADR-0027), so nothing changed in the kit.

### What changed

- `DragAutoscroll` records the edge, the last drag cell and the scroll position at which the selection was last extended.
  `ScreenController.isAutoscrolling` and `tick()` live in `ScreenController+Autoscroll.swift`; `AutoscrollTimer` posts `.tick` while wanted.
- `FrameGeometry.scrollback` records the position a frame was drawn at. A tick acts only on a frame that shows the controller's
  current position, so it never extends the selection over a line it has not seen and never scrolls twice for one frame.
- `ScreenEvent` moved to its own file and the timer to its own type, so `InteractiveScreen.swift` stays under the 250-line ceiling.
- The interval is a 50 ms constant, not a `ui.*` key. Open question for the owner: should the rate be tunable?

### Evidence

| Claim | Probe | Result |
|---|---|---|
| A held drag scrolls to the start and the selection reaches the first line | `AutoscrollTests` (7) | Pass after one real defect (below) |
| A step waits for the frame that shows the last scroll | stale-frame test | Pass; mutant that ignores staleness caught |
| The selection grows by the line that scrolled in | growth test | Mutant that never extends caught by 4 tests |
| The timer is wired in the real binary | `probe-pointer.py`, two new checks (26/26) | A binary with the timer disabled fails exactly those two |
| Existing contracts | pointer, folding (all), input (19) PTY probes | Pass; the restored binary is byte-identical to the one that passed |

The first version stopped the timer as soon as there was nothing left to scroll, which stopped it **before** the selection was extended
over the last line that scrolled in: the copied text began at line 2, not line 1. The red tests found it; `extendedAt` fixed it.

One mutant survived: ignoring `selector.isDragging` in `isAutoscrolling`. It is equivalent today, because a drag's end also clears the
request. The guard stays as a second, independent reason to stop; it is not a tested one.

The pointer probe's fixtures are pyte and a PTY, not a physical terminal. Real rate and trackpad feel are unverified.

### Costs (release, same machine, not idle)

`thinking/.*` benchmarks, same harness as diary 55: unchanged frames **11 µs, 3 allocations** (ordinary, folded and open), as before; opening a
400-line block 2.597/2.642/2.683 ms p25/50/75 and 1,284 allocations, against 2.621/2.658/2.710 ms and 1,284 before. The frame stores one more
integer. A tick that changes nothing draws nothing, and the timer exists only during a held edge drag.

`Scripts/measure-budgets.py`, 20 runs, ordinary release binary, 1-minute load 4.3 and falling at the start (not an idle machine):
cold 13.94 ms median (p95 24.75, max 31.06), RSS 9,968 KiB, input 0.32 ms (max 0.80), action 2.80 ms (p95 3.34). All medians inside budget.
This change does not touch startup; the earlier 32 ms cold median was taken at load about 11, and this one is evidence that load moves
that number a great deal, not a speedup.
