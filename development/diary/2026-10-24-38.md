# Diary — 2026-10-24 (38)

## The file tools' check-then-use race, measured and closed (roadmap 0058, ADR-0085)

The caveat I had reported at the end of every summary: ADR-0035 says a path check and its use are two steps, so a swapped link could
redirect a write. Nobody had shown it could. Worktree `ask-toctou` from `d81a272`; direct commands only.

## Measured first

A temporary test: a thread flips `work/d` between a real directory and a symlink to ask's configuration directory as fast as it can,
while the real `WriteTool` writes `d/pwn.txt` 6,000 times under the default policy. Three runs: 0, 2 and 2 files landed in the
configuration directory (the directory that holds `credentials.json` and `config.json`; a sandboxed job can race a file tool, which is
all the attack needs). A swap made at exactly the right instant, through a hook between the check and the use, read the protected
credentials. The race was real, the escape was real, and the existing "canonical path" mitigation did not stop it.

## What was built

`ScopedFile` (`AskTools`): under a restricted policy a read opens the file, asks the kernel where the descriptor is, authorizes that
real path and reads from the descriptor; a write opens the deepest existing directory, authorizes it, makes missing directories with
`mkdirat` and enters them with `openat`, writes a temporary file there and renames it with `renameat`, keeping the permissions of what
it replaces. `FileTools.text` and `FileTools.write` take the context and an optional `between` closure, which only tests use to put the
swap exactly between the check and the use. Unrestricted runs keep the old code.

## Evidence

| What | Result |
|---|---|
| Before | 2 of 6,000 racing writes landed in the protected directory (twice in three runs); the read of the swapped directory returned the secret; the hook tests failed, all of them |
| After | 11 tests pass (deterministic swaps for a read, a write, a write that creates directories, a target readable but not writable, and a protected file inside an allowed directory, plus the behaviours that must keep working); 15 runs of a 2,000-write stress test, 30,000 racing writes, none landed |
| Compiling mutants | 14, all caught by a named assertion (3 needed new tests, below) |
| Strict gate | passes |

## What the mutants found missing

- **A write verified for read instead of write** survived: my race target was a directory that is neither readable nor writable, so
  the capability checked did not matter. The state directory (readable, not writable) is a target where it does.
- **A verified path that forgot the file's name** survived: the swap target was a whole protected directory. `~/.ssh` is allowed but
  holds one protected file (`id_ed25519`), which only the name in front of the real directory protects.
- **Permissions not kept** was a mutant that did not compile (an unused value), rewritten.

Two `O_NOFOLLOW` mutants are not in that list because they are equivalent: the check on the descriptor is what protects, and the flag
only changes which message fails first.

## What I did not probe

The real binary. A race needs thousands of file tool calls; each is a model turn through the fake provider, and at the measured
rate of about one in 3,000 the probe would be a coin toss before the fix and nothing to see after. The tests drive the real
`WriteTool` and `ReadTool` with a policy built by the same function the binary uses.

## Mistakes

- I left a pointless trailing block in one test (a decoy file and an unlink I had thought about and not needed) and read it back before running.
- `read` and `write` inside an enum with static `read`/`write` methods resolve to the wrong function; they needed `Darwin.` in front.
- `ToolFailure` has `output`, not `message`; found by the compiler.
