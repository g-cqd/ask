# 2026-11-15 (07): a session, a prompt, its updates, its answer

Roadmap 0234 step 2, the third step of ADR-0154's order, in `AskACP` alone: `session/new` and `session/prompt` against the
screen's `Conversation` seam, with a conversation the test directs. No real conversation is served yet; `ask serve` still makes
no sessions.

Read from the specification before writing (the `.md` form of each page: Session Setup, Prompt Turn, Content, Errors):
`session/new` takes `cwd`, an absolute path, and answers `sessionId`; a prompt is content blocks, of which every agent takes
`text` and `resource_link`; updates are `session/update` notifications naming the session; the answer is a stop reason and must
follow the turn's last update; a session that is not active is `-32002` with `data.sessionId`.

| Claim | Probe | Verdict |
|---|---|---|
| A turn's updates reach the client in the order said, and its answer after them | a directed conversation says thought, thought, text, text, end; the client's log is read | **Holds**: each update is sent before the next is read |
| What is said after a turn's end is not the turn's | text, end, text, said at once | **Fails** at first: the stream had the third buffered, and finishing a stream does not drop what it holds. The loop now leaves at the end |
| A failed turn says why | an error notice, a plain notice, `returnQueuedPrompts`, end | **Holds**: `-32603` with the error's words, not the later notice's |
| A prompt during a turn steers it | a second `session/prompt` while the first waits | **Holds**: offered as steering; both answered at the turn's end; one the turn did not take starts the next turn; a failed turn answers both with its failure; a refused one is told why and the turn goes on |
| The tests can fail | six mutations at once (the failure dropped, any notice taken as the reason, the path check, the chunk's kind, a list not flattened, a file link left as a URI), then two in the steering | **Holds**: eleven tests red, then two |
| A broken server fails a test and does not hold it | the first mutation run | **Fails** at first: it never ended, and was killed after 400 s. A wait on a continuation is not ended by a time limit. The test client's waits (`ACPExchange.answer`, `Mailbox.next`) now end when the test is cancelled; the same mutations then fail in 64 s |
| They hold on one thread | `LIBDISPATCH_COOPERATIVE_POOL_STRICT=1`, the 27 tests | **Holds** |

Built: `ACPSession` (a conversation and its id, made by a source the server is given), `ACPSessions`, `ACPTurns` (the turn and
the prompts sent during it), `ACPPrompt` (the blocks to text), `ACPUpdate` (the conversation's updates to ACP's, a switch with
no default: every update is listed as sent, or as not and why). `AskACP` now depends on AskTUI for the seam.

Decided here, small enough not to ask: a file link in a prompt is written as its path and any other as its address, where the
client put it; a prompt with nothing in it is refused; a server with no source has no session methods (`-32601`), which is what
`ask serve` is until the next step.

Known and not yet handled: `mcpServers` of `session/new` is read past, not connected. `session/cancel` waits for the pin
(ADR-0154). When the client's input ends during a turn, the turn runs to its end before ask exits. With a prompt promoted to
the next turn, that turn's first update can be written before the previous turn's answer.
