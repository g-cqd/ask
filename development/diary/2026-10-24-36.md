# Diary — 2026-10-24 (36)

## Addressing the formal-models report: cuts fall between characters, and a buffer that keeps nothing keeps nothing (roadmap 0057 complete, ADR-0083)

Third fault of the report, plus the first of its "read, not probed" items, which lives in the same file. Same worktree.

## What was built

`UTF8Cut` (`AskAgentCore`): `droppingPartialEnd` and `droppingPartialStart` take a partial character off a head's end and a tail's
start, at most three bytes each and nothing on a boundary. `OutputBuffer.text` and `Compaction.clipped` use them, and their omission
notes count every byte not shown, so shown plus counted is the stream. `Compaction.clipped` copies only the two ends, as before,
not the whole text.

Not in the report, found by reading `text` while fixing it: a stream nothing was omitted from was still decoded head and tail apart, so
a character straddling the 512 KiB boundary of a whole stream came out as U+FFFD. It is decoded as one now.

`OutputBuffer(keeping: 0)` trapped (`% keeping`, then an index). Probed first with an exit test: `SIGTRAP`, red. It keeps nothing and
counts everything as omitted now, and `isEmpty` accounts for omitted bytes, because a buffer that dropped everything it was given is not
empty. Clamping to one byte would have kept output the caller had asked not to keep.

## What I did not prove, and why

- **The real binary for the cuts.** `OutputCap` (50 KiB) sits in front of a tool result and already cuts on scalar boundaries, so the
  `OutputBuffer` cut at 512 KiB is not visible to the model unless the cap is raised, and a probe of it through the real binary has
  nothing to see. I started one, saw the result was the short pointer to the output file, and deleted it instead of making it say
  something. `Compaction.clipped` is reachable through `/compact`, but staging a conversation long enough for it to summarise is a
  lot of machinery for a cosmetic fault; the unit tests drive the function directly. The join was probed with the real binary (diary 35).
- **One equivalent mutant.** Searching back three bytes instead of four for a lead byte changes nothing: a four-byte character whose
  four bytes are all present is left alone either way.

## Mistakes

- A mutant that did not compile (the marker's count) was rewritten so the unused values still compile, and one assertion in my own test
  expected three bytes where the helper gives up three at most and the input had four leading continuation bytes; the test was wrong.
- `Compaction.clipped` first became `Array(text.utf8)` before the length check, which would have copied a multi-megabyte string on the
  common path of "it fits". Caught by rereading the diff before the tests, not by a test.
- `OutputCap.scalarCut` is a second implementation of the same boundary rule. I left it alone (it works, and is not what the report
  was about) and recorded it in the ADR; unifying them is a small follow-up.
